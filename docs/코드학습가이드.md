# assit 백엔드 코드 학습 가이드 — 스웨거 눌러보며 코드 따라가기

> 대상: FastAPI를 처음 보는 팀원. 스웨거(`/docs`)에서 API를 하나 호출할 때마다
> **"어떤 코드가 어떤 순서로 도는지"**를 따라가며, 그 자리에 쓰인 문법을 함께 익힌다.
> 준비: `docker compose up -d db` → `uvicorn app.main:app --reload` → http://localhost:8000/docs

---

## 0단계. 지도 먼저 — 요청 하나가 지나가는 길

스웨거에서 어떤 버튼을 누르든 요청은 **항상 이 5칸을 순서대로** 지난다:

```
브라우저 요청
   │
   ▼
① app/main.py        FastAPI 앱 — "어떤 URL이 어떤 함수인지" 등록(라우터 include)
   │
   ▼
② app/routers/*.py   라우터 — URL·파라미터 받기, 의존성 주입, 응답 스키마 지정 (얇게)
   │
   ▼
③ app/deps.py        의존성 — DB 세션 열기, 쿠키에서 사용자 세션 찾기, 로그인 검사
   │
   ▼
④ app/services/*.py  서비스 — 실제 비즈니스 로직 (DB 조회·판단·조립). 여기가 본체
   │
   ▼
⑤ app/schemas/*.py   응답 스키마 — 서비스가 준 dict를 검증·직렬화해 JSON으로
```

그리고 **사용자 요청과 무관하게 뒤에서 도는 두 개**:

```
app/scheduler.py ──06:00──▶ app/collectors/*  (외부 API → DB)  ──▶ app/ai/*  (DB → OpenAI → DB)
```

**핵심 원칙 하나만 기억**: 사용자 요청(위 ①~⑤)은 **DB만 읽는다.** 외부 API·OpenAI는 배치가 미리 끝내둔다.
유일한 예외가 용어 풀이(`/terms/explain`) — 8단계에서 본다.

### 디렉터리 한눈에

| 폴더 | 역할 | 비유 |
| --- | --- | --- |
| `app/routers/` | URL ↔ 함수 연결 | 식당 홀 직원 (주문 받기) |
| `app/services/` | 로직 | 주방 (요리) |
| `app/schemas/` | 요청·응답 형식 | 메뉴판·접시 규격 |
| `app/models.py` | DB 테이블 정의 | 창고 선반 구조 |
| `app/deps.py` | 공통 준비물 | 손 씻기·앞치마 (매 주문마다) |
| `app/collectors/` | 외부 데이터 수집 | 새벽 장보기 |
| `app/ai/` | LLM 요약·RAG·가드레일 | 재료 손질 |
| `data/*.json` | 매핑표(업종·부처·폼 해설) | 레시피 노트 (코드 수정 없이 바꿈) |
| `scripts/` | 1회성 실행 도구 | 개점 준비 체크 |

## 1단계. `POST /session` — 앱에 처음 들어온 순간

### 스웨거에서
`POST /session` → Try it out → Execute. 응답:
```json
{"created": true, "authenticated": false, "stocks": ["005930", "000660", ...]}
```
응답 헤더에 `set-cookie: assit_session=...`가 붙는다. **이후 모든 호출에 스웨거가 이 쿠키를 자동으로 실어 보낸다.**

### 코드 따라가기

**① `app/main.py`** — 앱 조립
```python
app = FastAPI(title="assit API", lifespan=lifespan)
register_exception_handlers(app)          # 에러를 {code, message, details}로 통일 (뒤에서 설명)
app.include_router(sessions.router)       # "sessions.py에 정의된 URL들을 앱에 붙여라"
...
```
> **문법: `lifespan`** — 서버가 켜질 때/꺼질 때 한 번 실행되는 함수. 여기선 `init_db()`(테이블 생성)와
> 스케줄러 시작을 한다. `yield` 앞이 "켜질 때", 뒤가 "꺼질 때".

**② `app/routers/sessions.py`** — URL 받기
```python
router = APIRouter(tags=["session"])                # 라우터 = URL 묶음. tags는 스웨거 그룹 이름

@router.post("/session", response_model=SessionResponse)
def create_session(request: Request, response: Response, db: DbDep) -> SessionResponse:
    session, created = ensure_session(db, request.cookies.get(COOKIE_NAME))
    response.set_cookie(COOKIE_NAME, session.id, max_age=..., httponly=True, samesite="lax")
    return SessionResponse(created=created, authenticated=session.authenticated, stocks=...)
```
> **문법 3개가 한 번에 나온다:**
> - `@router.post("/session")` — **데코레이터**. "POST /session이 오면 바로 아래 함수를 실행해라." `.get/.post/.put/.delete`가 HTTP 메서드.
> - `response_model=SessionResponse` — 반환값을 이 Pydantic 스키마로 **검증하고 JSON으로 바꿔라.** 스웨거의 응답 예시도 여기서 자동 생성된다.
> - `db: DbDep` — **의존성 주입**. 함수 인자에 타입만 적으면 FastAPI가 알아서 DB 세션을 만들어 넣어준다. (③에서 설명)
>
> **왜 `async def`가 아니라 `def`인가?** — 이 프로젝트 규칙(CLAUDE.md 불변식 2). 우리는 DB를 동기(sync) SQLAlchemy로 쓰는데,
> `async def` 안에서 동기 DB를 부르면 서버 전체가 멈춘다. `def`로 쓰면 FastAPI가 알아서 스레드풀에서 돌려 안전하다.

**③ `app/deps.py`** — 의존성이 뭔지
```python
DbDep = Annotated[Session, Depends(get_db)]
```
> `Depends(get_db)`는 "이 값이 필요하면 `get_db()`를 먼저 실행해서 결과를 넣어라"는 뜻.
> `get_db`는 `app/db.py`에 있다:
> ```python
> def get_db():
>     db = SessionLocal()      # DB 연결 하나 열고
>     try:
>         yield db             # 라우터 함수에게 빌려준 뒤
>     finally:
>         db.close()           # 요청이 끝나면 반드시 닫는다
> ```
> `Annotated[...]`로 별칭을 만들어 두면 모든 라우터에서 `db: DbDep` 한 단어로 쓴다. 이 파일에 이런 별칭이 4개 있고, 전부 이 패턴이다:
>
> | 별칭 | 의미 | 없으면 |
> | --- | --- | --- |
> | `DbDep` | DB 세션 | — |
> | `OptionalSession` | 쿠키에 세션 있으면 주고, 없으면 None | 그냥 None (에러 아님) |
> | `CurrentSession` | 세션 필수 | 401 `no_session` |
> | `AuthSession` | 세션 + 로그인 필수 | 401 `login_required` |
>
> 라우터 함수 인자에 어느 별칭을 쓰느냐가 곧 **"이 API의 인증 수준"**이다. 코드 읽을 때 이것만 봐도 접근 규칙을 알 수 있다.

**④ `app/services/sessions.py`** — 로직
```python
def ensure_session(db, session_id):
    if session_id:
        existing = db.get(UserSession, session_id)          # PK로 한 건 조회
        if existing is not None and existing.expires_at >= utcnow():
            return existing, False                          # 유효 세션 재사용 (멱등)
    session = UserSession(id=uuid.uuid4().hex, expires_at=utcnow() + timedelta(days=30))
    db.add(session); db.flush()                             # INSERT 예약 → id 확정
    provision_default_stocks(db, session)                   # 기본 종목 4개 (시총 상위 보통주)
    db.commit()                                             # 실제 저장
    return session, True
```
> **문법(SQLAlchemy)**: `db.get(모델, pk)` = 기본키 조회 / `db.add()` = 저장 예약 / `db.flush()` = DB에 보내되 확정은 아직 /
> `db.commit()` = 확정. `db.query(모델).filter(...).all()` 이 조회의 기본형이고, 이 프로젝트 전체가 이 몇 개로 돌아간다.

**⑤ `app/schemas/sessions.py`** — 응답 형식. `class SessionResponse(BaseModel): created: bool ...` — Pydantic 모델.
필드 타입을 적어두면 검증·JSON 변환·스웨거 문서가 전부 자동이다.

### 이 단계에서 익힌 것
데코레이터로 URL 등록 → 인자 타입으로 의존성 주입 → 서비스가 DB 조작 → 스키마로 응답. **모든 API가 이 틀이다.** 나머지 단계는 이 틀 위에 "무엇이 다른가"만 본다.

## 2단계. `GET /markets` — 화면 골격 (국내/해외 탭)

### 스웨거에서
응답: 국내 `tabs: [youtube, disclosure, regulation, bok, fed]`, 해외는 bok 없음. `stock_count`, `last_stock_code`, 해외는 종목 없으면 `reason: no_overseas_stock`.

### 코드
- `app/routers/markets.py` → `app/services/markets.py`의 `TABS_BY_MARKET` 딕셔너리가 **탭 구성의 단일 진실**. 프론트는 이걸 받아 탭을 그리고, 하드코딩하지 않는다.
- 같은 파일의 `validate_combination(market, tab)` — "해외 종목 + 한국은행 탭" 같은 잘못된 조합을 `invalid_combination`(400)으로 거른다. 5단계 카드 조회가 이걸 재사용한다.
- `session: OptionalSession` — 세션 있으면 종목 수·복귀 지점을 채우고, 없어도 동작(첫 진입 대비).

### 여기서 볼 문법 — 에러 처리 통일
서비스에서 `raise AppError("invalid_combination", "…", 400)`을 던지면, `app/errors.py`의 핸들러가 잡아서 항상 같은 모양으로 응답한다:
```python
@app.exception_handler(AppError)
async def app_error_handler(request, exc):
    return JSONResponse(status_code=exc.status_code,
                        content={"code": exc.code, "message": exc.message, "details": exc.details})
```
> 그래서 프론트는 어떤 API든 `code`만 보고 분기하면 된다. **라우터·서비스 어디서든 `raise AppError(...)`만 던지면 끝** — 응답 포맷을 신경 쓸 필요가 없다. 검증 실패(422)도 같은 포맷으로 감싼다.

## 3단계. `GET /stocks/search?q=삼성&market=domestic` — 검색

### 스웨거에서
`q=삼성` → 삼성전자·삼성전기… 시총순. `q=테슬라&market=overseas` → TSLA. `q=엔비디아`(화이트리스트 밖이면) → `reason: unsupported_overseas`.

### 코드 — `app/services/stocks.py`의 `search_stocks`
```python
results = (db.query(StockMaster)
    .filter(StockMaster.market == MARKET_DOMESTIC,
            StockMaster.name.ilike(f"%{q}%") | StockMaster.stock_code.like(f"{q}%"))
    .order_by(StockMaster.market_cap.desc().nullslast())
    .limit(SEARCH_RESULT_LIMIT).all())
```
> **문법(쿼리 파라미터)**: 라우터 함수 인자 `q: str, market: str`처럼 **경로에 없는 인자는 자동으로 `?q=...` 쿼리 파라미터**가 된다. 타입 검증도 자동(문자열 아닌 값 오면 422).
> **문법(SQLAlchemy)**: `.filter(A | B)`가 OR, `.filter(A, B)`가 AND. `ilike`는 대소문자 무시 LIKE.

- 해외 검색은 별칭(`aliases` JSON 배열)까지 본다 — "테슬라"·"tesla" 모두 TSLA.
- 화이트리스트 밖 유명 종목은 `data/unsupported_overseas.json`과 대조해 "오타가 아니라 미지원"임을 알려준다 (UX 결정, 명세 F-3.3.1).

## 4단계. `POST /auth/mock-login` → `POST /me/stocks` — 로그인 게이트

### 스웨거에서
① 로그인 **전에** `POST /me/stocks` `{"stock_codes": ["005930"]}` → **401 `login_required`**
② `POST /auth/mock-login` `{"id": ..., "password": ...}` (.env의 MOCK_LOGIN 값) → 200
③ 다시 `POST /me/stocks` → 200, `added` 목록

### 코드 — 인증은 인자 타입 한 단어
```python
# app/routers/me_stocks.py
@router.get("/me/stocks")
def my_stocks(market: str, session: CurrentSession, db: DbDep): ...     # 세션만 있으면 됨

@router.post("/me/stocks")
def add_stocks(body: StockAddRequest, session: AuthSession, db: DbDep, background: BackgroundTasks):
    added, skipped = stock_service.add_stocks(db, session, body.stock_codes)
    for stock in added:
        background.add_task(collect_on_stock_added, stock.stock_code)   # ★
    return StockAddResponse(...)
```
> **문법(요청 바디)**: `body: StockAddRequest` — Pydantic 모델을 인자로 두면 JSON 바디를 파싱·검증해 넣어준다.
> **문법(BackgroundTasks)**: ★ 줄이 중요. "응답을 먼저 보내고, 그 **뒤에** 이 함수를 실행해라." 새 종목의 공시·유튜브 수집은 외부 API를 부르는 일이라
> 요청 중에 하면 느리고 원칙 위반 → 응답 후 백그라운드로 뺀다. 사용자는 즉시 응답을 받고, 몇 초 뒤 카드가 채워진다.

`AuthSession`(deps.py) 안을 보면:
```python
def require_auth(session: CurrentSession) -> UserSession:   # 의존성이 다른 의존성을 쓴다 (체인)
    if not session.authenticated:
        raise AppError("login_required", "로그인이 필요합니다", status_code=401)
    return session
```
> 의존성은 **중첩**된다: `AuthSession` → `CurrentSession` → `DbDep`. 로그인 게이트가 이 프로젝트에 딱 두 곳(종목 추가·카드 저장)뿐인 것도 이 별칭을 검색하면 바로 보인다.

## 5단계. `GET /cards?tab=disclosure&stock_code=000660` — 핵심 화면 ★★★

이 프로젝트의 **가장 중요한 로직**. 여기만 제대로 이해하면 절반은 끝이다.

### 스웨거에서
응답의 카드 하나를 뜯어보자:
```json
{
  "card_id": 231, "label": "neutral", "label_reason": "…",
  "title": "주요사항보고서(자기주식처분결정)",           ← 원문 그대로 (AI가 손 안 댐)
  "summary_short": "SK하이닉스가 자기주식 82주를…",       ← AI 요약(목록용)
  "summary_full": "…",                                    ← AI 요약(상세 시트용)
  "details": [{"label": "처분 예정 금액", "value": "122,590,000원"}, …],  ← 정형 공시 배지
  "source_name": "DART", "published_at": "…", "origin_url": "…", "is_saved": false
}
```
`tab=bok`으로 바꾸면 `link_sentence`("금리가 오르면 이 업종은…")가 목록 위에 1개 붙고, `tab=youtube`면 요약은 null·`view_count`가 채워지고 `disclaimer: true`.

### 코드 — `app/services/cards.py`의 `list_cards` (위에서 아래로 읽으면 된다)

```python
def list_cards(db, session, tab, stock_code):
    stock = db.get(StockMaster, stock_code)                     # 1) 종목 확인 (없으면 404 unknown_stock)
    validate_combination(stock.market, tab)                     # 2) 구분×탭 조합 검사 (2단계 함수 재사용)
    if session and 등록된 종목이면: set_last_stock(...)           # 3) "마지막 본 종목" 갱신 (구분 전환 복귀용)
    items = _query_items(db, tab, stock)                        # 4) ★ 탭별로 원자료를 어떻게 찾나
    cards = [_build_card(db, tab, stock, item) for item in items]  # 5) 원자료 + AI 생성물 → 카드 dict
    _mark_saved(db, session, cards)                             # 6) 저장한 카드에 is_saved=true
    return {"tab": tab, "market": stock.market, "link_sentence": _link_sentence(...) if 금리탭 else None,
            "disclaimer": tab == "youtube", "reason": None if cards else _empty_reason(...), "items": cards}
```

**4) `_query_items` — 탭마다 "종목과 자료를 잇는 방식"이 다르다** (이게 데이터 모델의 핵심):

| 탭 | 조회 방식 | 테이블 |
| --- | --- | --- |
| youtube / disclosure | 종목에 **직접 링크**된 자료 | `source_item ⟵ source_item_stock(stock_code)` |
| regulation | 종목의 **업종**에 링크된 자료 | `source_item ⟵ source_item_industry(industry_key)` — 국내 12분류 / 해외 SIC |
| bok / fed | 종목 무관, **탭 전체** | `source_item WHERE tab='bok'` |

공시는 여기서 **노출 유형 필터**(`displayed_form_codes`)까지 건다 — PM 확정 12유형만. 수집은 전부 하고 화면에서만 거르니, 정책이 바뀌면 `data/disclosure_form_types.json`의 `display` 플래그만 고치면 된다.

**5) `_build_card` — 카드 조립**: `_generated_for()`가 이 원자료의 AI 생성물을 찾아온다. 이때 **"어느 단위의 생성물인가"**가 탭마다 다르다:
- 공시 → `scope="stock"`, 종목코드별 (같은 공시라도 종목마다 요약이 다를 수 있음)
- 규제 → `scope="industry"`, 업종별 (한 규제를 업종 단위로 1번만 요약해 공유 — 비용 절감)
- 금리 → `scope="global"` 1건

**6) `_empty_reason`**: 카드가 0건일 때 `collect_status` 테이블을 봐서 "수집이 실패한 건지(`fetch_failed`)" vs "진짜 자료가 없는 건지(`no_data`)"를 구분해준다 — 프론트가 다른 문구를 띄울 수 있게.

### 이 단계에서 반드시 짚을 DB 구조 (`app/models.py`)

```
source_item            원자료 1건 (tab·market·title·published_at·origin_url·content·detail_json…)
  ├─ source_item_stock       ─ 어느 종목 것인가 (공시·유튜브)
  ├─ source_item_industry    ─ 어느 업종 것인가 (규제)
  └─ generated_content       ─ AI 생성물 (scope·scope_key·summary·label·locked)
rate_link_sentence     "내 종목엔" 문장 캐시 (market·tab·업종·지표버전)
saved_card             저장 카드 (snapshot_json — 원본과 독립)
collect_status         수집 단위별 성공/실패 (빈 목록 사유 판정)
```
> **읽는 팁**: `models.py`의 각 클래스 docstring에 "F-몇 번" 명세 번호가 있다. 왜 이 컬럼이 있는지 궁금하면 그 번호로 `docs/assit_요구사항명세서_v3.md`를 찾으면 된다.

## 6단계. 그 카드는 어떻게 만들어졌나 — 수집 배치 (`app/collectors/`)

스웨거엔 없지만, 5단계 카드의 **원자료가 DB에 들어온 경로**. `scripts/collect_now.py`로 수동 실행해볼 수 있다(실키 필요).

### 흐름 — `app/collectors/runner.py`
```python
def collect_all(db):
    stocks = registered_stocks(db)                       # 세션들에 등록된 고유 종목 (중복 제거)
    result = collect_for_stocks(db, stocks)              # 종목 종속: 공시(DART/SEC) + 유튜브
    result["regulation"] = sync_regulations(db)          # 전역: 국내 규제 (업종→부처)
    result["us_regulation"] = sync_us_regulations(db)    #      미국 규제 (SIC→기관)
    result["bok"] = sync_bok_rate(db); result["fed"] = sync_fed_rate(db)   # 금리 지표
    result["purged"] = purge_old_items(db)               # 90일 지난 자료 정리 (저장 카드는 SET NULL로 생존)
```
`app/scheduler.py`가 매일 06:00에 이걸 부르고 이어서 AI 생성까지 체인으로 돌린다. 4단계의 종목 추가 백그라운드 훅은 `collect_for_stocks`를 새 종목 1개로만 부른다.

### 수집기 하나 뜯어보기 — `app/collectors/dart.py`의 `sync_disclosures`
읽을 때 이 패턴이 **모든 수집기에 공통**이다:
```python
for stock in stocks:
    try:
        resp = get_with_retry(LIST_URL, params={...})       # 지수 백오프 3회 재시도 (base.py)
        ... 파싱 ...
        item = upsert_source_item(db, tab=..., source_key=rcept_no, title=원문그대로, ...)  # 있으면 갱신, 없으면 삽입 (멱등)
        ensure_stock_link(db, item.id, stock.stock_code)      # 종목 링크
        db.commit()
        mark_status(db, "disclosure", stock.stock_code, True, ...)   # 성공 기록
    except Exception as e:                                    # ★ 한 종목 실패가 나머지를 막지 않는다
        db.rollback()
        mark_status(db, "disclosure", stock.stock_code, False, str(e))   # 실패 기록 → 5단계 fetch_failed의 근거
```
> **왜 upsert인가**: 매일 다시 수집해도 같은 공시가 두 번 들어가면 안 되므로 `(tab, market, source_key)` 유니크 키로 "있으면 갱신"한다. 재실행이 항상 안전(멱등)한 것이 이 프로젝트 전체의 설계 습관이다 — 스크립트를 몇 번 돌려도 데이터가 망가지지 않는다.

`_enrich_details`는 정형 6종(자기주식·증자·감자·소송)만 DART 상세 API를 접수번호로 조인해 `content`(요약 입력용 텍스트)와 `detail_json.slots`(카드 배지)를 채운다. 어떤 필드를 어떤 라벨로 쓰는지는 `data/dart_detail_map.json`.

**종목 ↔ 자료 연결 축 요약** (다른 수집기도 같은 논리):
- 국내 공시: 종목코드 → corp_code(DART 고유번호, 주 1회 갱신)
- 해외 공시(`sec.py`): 티커 → CIK, User-Agent 헤더 필수·초당 10회
- 규제(`briefing.py`, `fedreg.py`): 업종 → 부처/기관 → 키워드 2차 필터 → 업종 링크
- 유튜브(`youtube.py`): 검색어 `"{종목명} 주식"`, 쿼터 카운터 80% 가드, 종목당 24h 캐시

## 7단계. 요약은 어떻게 생겼나 — AI 가공 (`app/ai/`)

`scripts/generate_now.py`로 수동 실행 가능. 5단계 카드의 `summary_*`·`label`이 여기서 만들어진다.

### 파이프라인 — `app/ai/summarize.py`의 `generate_summaries`
```
원자료 1건 × 생성 단위(종목/업종/전역)마다:
  1) 이미 생성됐거나 locked면 건너뜀 (멱등·검수 보호)
  2) _input_text()  ─ 탭별 고정 입력 만들기 (공시: 제목+유형 해설+정형 필드 / 규제: 제목+본문 / 금리: 지표+요지)
  3) 프롬프트 = SYSTEM_COMMON + 입력 + (라벨 탭이면 LABEL_GUIDE) + (해외 규제면 RELEVANCE_GUIDE)
  4) _guarded_generate()  ─ ★ LLM 호출 → 가드레일 → 위반 시 재생성 1회 → 그래도 위반이면 그 필드만 비움
  5) generated_content에 저장
```

**LLM 호출 — `app/ai/llm_client.py`**: OpenAI에 `response_format: json_schema, strict: true`로 보낸다.
> 이게 **structured output**. "이 JSON 스키마 모양으로만 답하라"고 강제해서, 응답 파싱이 깨질 일이 없다. 스키마는 `app/ai/prompts.py`에 상수로 (`SUMMARY_LABEL_SCHEMA` 등). 프롬프트 문구도 전부 이 파일 — **AI 말투를 바꾸고 싶으면 이 파일만** 고친다.

**가드레일 — `app/ai/guardrail.py`**: LLM이 아니라 **정규식**(결정적)이다.
```python
find_violations(text)          # 매수·매도 권유 / 목표가·상승률 수치 단정 / 방향 예측 → 사유 목록
find_unsourced_numbers(text, source)   # 생성문의 금액·수량 숫자가 입력에 없으면 위반 (지어낸 숫자 차단)
find_stock_names(text, names)  # 연결 문장에 종목명 등장 → 위반
```
> "자사주 매수 **결정**"(사실)은 통과시키고 "매수 **추천**"(권유)만 잡도록 패턴이 짜여 있다. 테스트(`tests/test_ai.py`)에 오탐/미탐 케이스가 있으니 패턴을 고칠 땐 그 테스트로 확인.

**연결 문장 — `app/ai/link_sentence.py`**: `업종 profile × 현재 금리·방향` → 1~2문장. 캐시 키가 `(market, tab, 업종, "2.75%|인상")`이라 **금리가 안 바뀌면 재생성 안 함**(비용·표현 흔들림 방지).

**해외 규제 관련성(F-4.7.2)**: 스키마에 `relevant: bool`을 추가로 받아, false면 업종 링크를 지우고 카드를 만들지 않는다. 실측에서 207건 중 110건이 걸러졌다 — 이 필터가 없으면 절반이 잡음.

## 8단계. `POST /terms/explain` — RAG (요청 중 LLM을 부르는 유일한 곳) ★★

### 스웨거에서
`{"term": "PER", "tab": "disclosure", "context": "PER이 낮다는 평가가…"}` → 응답에 `explanation` + **`sources: [{"term": "주가수익비율(PER)", "source": "bok_700", "similarity": 1.0}]`**. 두 번째 호출은 `cached: true`(LLM 안 부름). `"term": "김치볶음밥"`처럼 무관한 단어는 `sources: []`.

### 코드 — `app/routers/terms.py` → `app/ai/term_explain.py`
```
라우터: 50자 상한·탭 검사 → term_cache 조회(히트면 즉시 반환) → 레이트리밋(세션 20/분·IP 60/분) → 생성
생성(term_explain.py):
  1) find_exact_term()   ─ 표제어 정확 일치? ('PER' → '주가수익비율(PER)') 있으면 그것이 근거 (임베딩 생략)
  2) 없으면 client.embed([term]) → search_knowledge()  ─ pgvector 코사인 top-3, 유사도 0.45 미만은 버림
  3) 근거를 프롬프트에 주입 → LLM(정의까지만, 영향 판단 금지) → 가드레일 → 응답에 근거 목록 동봉
```

**RAG란** — `app/ai/rag.py` + `scripts/seed_knowledge.py`:
- 한국은행 「경제금융용어 700선」 685건 + 공시 유형 해설을 미리 **임베딩**(텍스트→1536개 숫자 벡터)해서 `knowledge_chunk` 테이블(pgvector)에 넣어둠. 청킹은 "용어 1개 = 청크 1개"(정의가 이미 의미 단위라 안 자름).
- 검색은 코사인 유사도(벡터 각도). `KnowledgeChunk.embedding.cosine_distance(query)`가 pgvector 연산자. 701행이라 인덱스 없이 1ms 미만 — 수만 건 되면 HNSW 인덱스 한 줄 추가.
- **왜 하냐**: 금융 용어는 LLM이 그럴듯하게 틀리기 좋은데, 한국은행 공식 정의를 근거로 주면 환각이 줄고 "출처가 한국은행"이라고 사용자에게 보여줄 수 있다. 심사 기준 "RAG 설명 가능성"에 대한 답이 응답의 `sources` 필드다.

**레이트리밋 — `app/services/ratelimit.py`**: 프로세스 메모리의 슬라이딩 윈도. uvicorn 워커가 1개라 가능한 단순 구조(워커 늘리면 깨짐 — 그래서 워커 1개가 불변식).

## 9단계. `POST /me/saved-cards` → `GET /me/saved-cards` — 저장

### 스웨거에서
`{"card_id": 231, "stock_code": "000660"}` (로그인 필요) → `item.snapshot`에 카드 내용 복사본. 같은 걸 또 저장하면 `already_saved: true`. `GET`은 국내·해외 통합 최근순 + `?stock_code=` 필터. `DELETE /me/saved-cards/231`.

saved = SavedCard(session_id=..., source_item_id=card_id, tab=item.tab, stock_code=...,

## 부록 A. FastAPI 문법 치트시트 (이 프로젝트에 나오는 것만)

| 문법 | 뜻 | 어디서 봤나 |
| --- | --- | --- |
| `@router.get("/path")` | URL 등록 데코레이터 | 모든 라우터 |
| `def f(q: str)` | 경로에 없는 인자 → 쿼리 파라미터 `?q=` | 3단계 검색 |
| `def f(body: SomeRequest)` | Pydantic 모델 인자 → JSON 바디 | 4단계 종목 추가 |
| `def f(card_id: int)` + `"/x/{card_id}"` | 경로 파라미터 | 9단계 DELETE |
| `db: DbDep` (=`Annotated[Session, Depends(get_db)]`) | 의존성 주입 | 전부 |
| `response_model=XResponse` | 응답 검증·직렬화·문서화 | 전부 |
| `raise AppError(code, msg, status)` | 통일 에러 (`app/errors.py` 핸들러가 포맷) | 서비스 전반 |
| `background: BackgroundTasks` + `.add_task(fn, arg)` | 응답 후 실행 | 4단계 온디맨드 수집 |
| `lifespan` | 서버 시작/종료 훅 | main.py |
| `def` (not `async def`) | 동기 DB라 스레드풀 실행 | 이 프로젝트 규칙 |

**Pydantic**: `class X(BaseModel): a: int; b: str | None = None` — 타입만 적으면 검증·변환·문서 자동. `Field(min_length=1)` 같은 제약도 가능.
**SQLAlchemy(동기)**: `db.get(M, pk)` / `db.query(M).filter(...).order_by(...).limit(n).all()` / `.one_or_none()` / `db.add()` / `db.commit()` / `db.rollback()`.
