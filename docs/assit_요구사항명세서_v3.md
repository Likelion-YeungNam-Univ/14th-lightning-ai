F-1. 세션 · 로그인
로그인은 관문이 아니다. 비로그인으로 전부 열람하고 종목 추가와 카드 저장 두 지점에서만 요구한다.

실제 인증은 구현하지 않는다. 사전 설정 계정 하나를 입력하면 로그인된 것으로 처리하는 시연용 모의 구현이다.

데이터는 계정이 아니라 세션에 귀속시킨다. 계정이 하나뿐이라 계정에 붙이면 시연 중 여러 사람이 서로의 종목을 보게 된다.

[F-3.3] 종목 검색
종목명 또는 코드 검색
초성 검색 지원 여부, 최소 입력 길이 확정 필요
검색 대상은 현재 구분으로 한정한다 — 국내 화면에서 해외 종목이 결과에 섞이면 추가해도 그 화면에 나타나지 않는다. 종목명 부분 일치 + 코드 전방 일치. 등록된 종목은 already_added: true. 결과 없음은 200 + 빈 배열

[F-3.3.1] 화이트리스트 밖 검색

중
[F-3.4] 구분별 종목 목록 조회
종목 줄 데이터

market 파라미터로 해당 구분의 종목만 반환. display_order 포함 전량 반환(칩 7개 분기는 프론트 표시 규칙). 양쪽을 한 번에 주고 프론트가 거르게 하지 않는다 — 칩 한도가 구분별로 적용되므로 목록도 구분별이어야 계산이 맞는다
상
[F-3.5] 종목 추가
여러 종목 일괄 등록

등록 상한 10개 — 구분별로 각각 적용. 배열을 받는 벌크 등록이며 이미 등록된 종목은 무시(멱등). 상한 초과분이 섞여 오면 400 + 남은 자리 수를 함께 반환한다. 비로그인이면 401. 프론트에서 막더라도 서버가 상한을 다시 확인한다
상
[F-3.5.1] 추가 결과의 구분 반환
다른 구분에 들어간 경우

응답에 추가된 종목의 market을 포함한다. 국내 화면에서 해외 종목을 추가하면 그 종목은 지금 보는 화면에 나타나지 않으므로, 안내가 없으면 사용자는 추가가 실패한 줄 안다. F-3.3이 구분을 한정하면 이 경우는 줄지만, 별칭·코드 검색으로 여전히 발생할 수 있다
중
[F-3.6] 종목 삭제
등록 종목 제거

전량 삭제를 허용한다. 0개가 되면 프론트가 빈 상태 화면으로 전환한다. 응답에 해당 구분의 남은 개수 포함. 삭제한 종목의 저장 카드는 유지
상
[F-3.7] 노출 순서 변경
앞에 보일 종목 지정

중
[F-3.8] 기본 종목 프로비저닝
신규 세션에 4개 등록

세션 생성 시점에 국내 시가총액 상위 보통주 4개 등록. 우선주는 종목코드 규칙으로 제외. 해외는 프로비저닝하지 않는다. is_default 플래그로 종목 추가 전환율(핵심 지표) 산출. 시총 순위가 매일 갱신되므로 기본 종목이 날마다 바뀔 수 있다

[F-6.6] 원문 링크 노출 위치

(제안) origin_url은 응답에 항상 담되 목록 카드에는 버튼을 두지 않고 시트에만 노출한다. 원문은 요약을 읽고 나서 가는 것이고, 부록 D의 "시트 대비 원문 이동률" 지표도 그래야 측정된다

[F-7.3] 저장 스냅샷
저장 시점 내용 고정

저장 시점의 제목·요약(단문·전문)·라벨·판단 이유·출처·날짜를 복사해 보관한다. 원자료가 갱신되거나 요약이 재생성되어도 저장본은 바뀌지 않는다. 원문 링크만 살아 있는 링크로 두고, 링크가 만료돼도 저장한 요약은 남는다
상
[F-7.4] 저장됨은 구분에 묶이지 않는다
국내·해외 통합 반환

어느 구분에서 열어도 저장한 카드 전부를 반환한다. 구분별로 나눠 보관하면 사용자가 어느 쪽에 담았는지 기억해야 찾을 수 있다. 저장은 자료의 국적이 아니라 사용자에게 귀속된다
상
[F-7.5] 저장됨 목록 조회
저장한 카드 반환

최근 저장 순. 각 항목에 저장 당시의 탭·종목을 배지용 필드로 반환(출처 맥락이 없으면 왜 저장했는지 기억나지 않는다). stock_code 파라미터로 종목 필터 지원
