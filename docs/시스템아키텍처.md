## 1. 한 장 요약

**대상은 국내 상장 주식(KOSPI·KOSDAQ)만이다.** 해외 종목은 명세상 범위 밖(검색에서 제외하고 `unsupported_overseas` 안내만).

```mermaid
flowchart LR
    subgraph USER["사용자 요청 경로 (실시간)"]
        U[사용자 브라우저] --> V["프론트 (Vercel)"]
        V -->|"/api/* 프록시"| API["FastAPI 서버 (가비아, 단일 프로세스)"]
        API --> DB[("PostgreSQL + pgvector")]
    end

    subgraph BATCH["배치 경로 (매일 06:00 + 종목 추가 시)"]
        SCH["스케줄러 (APScheduler)"] --> COL["수집기 collectors/"]
        COL --> EXT["외부 API<br/>KRX · DART · 정책브리핑<br/>ECOS · FRED · YouTube"]
        COL --> AI["AI 가공 ai/<br/>요약·라벨·문장 (Claude)"]
        AI --> DB
        COL --> DB
    end
```

**가장 중요한 설계 원칙 (CLAUDE.md 불변식 1):** 위 두 경로는 분리되어 있다. 사용자가 화면을 여는 순간에는 **DB만 읽는다** — 외부 API도 LLM도 부르지 않는다. 수집과 AI 생성은 전부 배치에서 미리 끝내 DB에 저장해 둔다. 그래서 시연 중 외부 API가 죽어도 화면은 멀쩡하다. (유일한 예외: 용어 풀이 `POST /terms/explain` — 사용자가 단어를 드래그하는 순간 LLM 1회 호출)

## 2. 데이터가 흐르는 순서

```mermaid
flowchart TD
    A["① 수집 (배치, collectors/)<br/>KRX 종목마스터 · DART 공시 · 정책브리핑 규제<br/>ECOS/FRED 금리 · YouTube 영상"]
    --> B["② 원자료 저장 (source_item)<br/>제목은 원문 그대로, 가공 금지"]
    --> C["③ AI 가공 (배치, ai/)<br/>요약 2단 생성 + 긍/중/부 라벨 + 판단 이유<br/>규칙: 가드레일 통과분만 저장, 유튜브는 요약 없음"]
    --> D["④ 생성물 저장 (generated_content)"]
    --> E["⑤ 조회 API (routers/)<br/>GET /cards?tab=&stock_code=<br/>다섯 탭 공통 스키마, 없는 필드는 null"]
    --> F["⑥ 프론트 렌더링<br/>카드 목록 + 요약 시트"]
```

RAG(F-4.8)는 ③에 끼어든다: 용어 풀이·공시 요약을 생성할 때, 미리 임베딩해 둔 지식베이스(한국은행 경제금융용어 700선 + DART 공시유형 해설)에서 관련 내용을 검색해 프롬프트에 근거로 넣는다.

## 3. 사용자 기능 흐름 (PRD 시나리오 기준)

```mermaid
flowchart TD
    S1["첫 진입 → 세션 발급 (쿠키, 30일)<br/>기본 종목 4개 자동 등록"] 
    --> S2["다섯 탭 자유 열람 (로그인 불필요)<br/>유튜브·공시·규제·한국은행·Fed"]
    --> S3["종목 추가 시도 → 여기서 처음 로그인 요구 (401)<br/>모의 로그인: 미리 정한 계정 하나"]
    --> S4["내 종목 카드 열람<br/>카드 탭 → 요약 시트 → 모르는 단어 드래그 → 용어 풀이"]
    --> S5["카드 저장 (로그인 필요)<br/>저장 시점 스냅샷 고정 → 저장됨 탭"]
```

로그인이 관문이 아니라는 것, 데이터가 계정이 아닌 **세션**에 붙는다는 것이 구조의 핵심이다(시연용 단일 계정이라 계정에 붙이면 관객끼리 데이터가 섞인다).

별도로 "다운로드해야 할 데이터셋"은 없다. 원자료(공시·규제·금리·영상)는 P3에서 API로 수집하고, RAG 지식베이스(경제금융용어 700선)는 P5에서 공개 자료를 1회 적재하며, 금통위 결정 요지만 수동 시드로 넣는다(연 8회 자료).

## 6. 남은 길 (개발계획서 P1~P6 요약)

```
P1 세션·종목 API ──→ P2 /cards 스키마 목 응답 (프론트 합류 지점)
                                │
P3 수집기 5종 + 배치 ──→ P4 AI 가공(요약·라벨·문장) ──→ P5 RAG·용어풀이·저장
                                                              │
                                              P6 배포·검수 잠금·캐시 워밍·리허설
```
