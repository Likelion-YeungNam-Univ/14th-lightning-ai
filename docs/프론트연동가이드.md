# 프론트 연동 가이드 (Next.js/Vercel 기준)

백엔드는 프론트 배포 여부와 무관하게 준비 완료 상태다. 이 문서 하나로 연동을 시작할 수 있다.

## 0. 키 없이 5분 시작 (가비아 배포 전 로컬 연동 — 권장)

실데이터(수집·AI 요약 완료본)가 담긴 DB 덤프가 저장소에 들어 있다. **API 키 없이** 아래
네 줄이면 전 탭이 실데이터로 응답하는 백엔드가 뜬다:

```bash
git clone <repo> && cd 14th-lightning-ai
cp .env.example .env                # 값 안 채워도 됨 — 조회 API는 키를 안 쓴다
bash scripts/restore_seed.sh        # DB 기동 → 시드 복원 → 앱 기동까지 한 번에
open http://localhost:8000/docs     # 스웨거에서 바로 테스트
```

- **키가 필요 없는 이유**: 조회 API는 전부 DB만 읽는다(수집·AI 생성은 백엔드 배치의 일).
  검색·카드·저장·이벤트 등 화면 개발에 필요한 모든 API가 키 없이 동작한다.
- **키가 필요한 두 가지**: ① 종목 추가 시 온디맨드 수집(유튜브·공시) ② 용어 풀이(OpenAI).
  이 흐름까지 실제로 테스트하려면 **노션에 정리된 .env 값**을 복사해 넣고 앱을 재시작하면
  된다(`docker compose restart app`). 비용 방어는 백엔드에 이미 있다(유튜브 쿼터 80% 가드,
  종목당 24h 캐시, 용어 풀이 분당 20회 제한).
- ⚠️ **.env는 어떤 저장소에도 커밋 금지** — 값은 노션에서만 관리한다.
- 세션·저장 카드 등 로컬에서 만든 데이터를 초기화하고 싶으면 `restore_seed.sh`를 다시
  실행하면 시드 상태로 돌아간다.

## 1. 접속 방식 — Vercel rewrite 프록시 (확정사항 4절)

프론트가 백엔드를 **직접 호출하지 않고** Vercel이 `/api/*` 요청을 백엔드로 대신 전달한다.
브라우저 입장에서 같은 도메인이라 **CORS 설정이 필요 없고**, 세션 쿠키도 그대로 동작한다.

```js
// next.config.js
module.exports = {
  async rewrites() {
    return [
      {
        source: "/api/:path*",
        destination: "http://<가비아서버IP>:8000/:path*", // 8/18 서버 확보 후 값 전달 예정
      },
    ];
  },
};
```

- 프론트 코드에서는 `fetch("/api/cards?tab=disclosure&stock_code=005930", { credentials: "include" })`처럼 **`/api` 접두사로 호출**하면 된다 (rewrite가 접두사를 떼고 전달).
- 로컬 개발도 동일: destination을 `http://localhost:8000/:path*`로 두면 된다.

## 2. 로컬에서 백엔드 통째로 띄우기

```bash
git clone <repo> && cd 14th-lightning-ai
cp .env.example .env        # 키 값은 백엔드 팀에게 받기
docker compose up -d        # DB + 앱 동시 기동 (localhost:8000)
```

- API 문서(스웨거): **http://localhost:8000/docs** — 전체 엔드포인트·스키마 자동 문서
- 시연 데이터 채우기(백엔드 팀이 실행): `collect_now` → `generate_now`

## 3. 엔드포인트 한 장 요약

| 메서드·경로 | 용도 | 인증 |
| --- | --- | --- |
| `POST /session` | 세션 발급(쿠키) — 앱 첫 진입 시 1회 | — |
| `POST /auth/mock-login` | 모의 로그인 | 세션 |
| `GET /markets` | 구분(국내/해외)별 탭 구성·종목 수·복귀 지점 | 세션 선택 |
| `GET /stocks/search?q=&market=` | 종목 검색 (미지원 해외 종목은 `unsupported_overseas`) | 세션 선택 |
| `GET /stocks/popular?market=` | 추천 칩 (국내 시총 상위 / 해외 화이트리스트) | — |
| `GET·POST·DELETE·PUT /me/stocks` | 내 종목 목록·추가·삭제·순서 (**추가만 로그인 필수**) | 세션 / 로그인 |
| `GET /cards?tab=&stock_code=` | 카드 목록 — 요약·라벨·정형 배지(`details`)·연결 문장 포함 | 세션 선택 |
| `POST /terms/explain` | 드래그 용어 풀이 (RAG 근거 `sources` 포함) | 세션 선택 |
| `GET·POST /me/saved-cards`, `DELETE /me/saved-cards/{card_id}` | 저장됨 (POST/DELETE 로그인 필수) | 세션 / 로그인 |
| `POST /events` | 지표 이벤트 적재 (아래 4절) | 세션 선택 |

공통 규칙:
- 에러는 항상 `{code, message, details}` — `code`로 분기 (예: `login_required`, `invalid_combination`, `rate_limited`)
- 빈 목록은 200 + `items: []` + `reason: no_data | fetch_failed`
- `/cards`에 market 파라미터는 없다 — 종목코드가 구분을 결정한다

## 4. 지표 이벤트 (F-8.2) — 프론트에서 쏴줘야 하는 11종

`POST /events` body: `{"event_name": "...", "payload": {...}}` — payload는 선택.

| event_name | 언제 | payload 예 |
| --- | --- | --- |
| `home_view` | 홈 화면 도달 | — |
| `market_switch` | 국내↔해외 전환 | `{"market": "overseas"}` |
| `first_tab_view` | 세션 최초 종목 탭 진입 | `{"tab": "youtube", "stock_code": "005930"}` |
| `tab_view` | 탭 진입할 때마다 | 동일 |
| `youtube_to_other_tab` | 유튜브 탭에서 다른 탭으로 이동 | `{"from_tab": "youtube", "to_tab": "disclosure"}` |
| `sheet_open` | 카드 눌러 요약 시트 열람 | `{"card_id": 123, "tab": "disclosure"}` |
| `origin_click` | 시트에서 원문 링크 클릭 | 동일 |
| `stock_add` | 종목 추가 성공 | `{"stock_code": "005930"}` |
| `login` | 로그인 성공 | — |
| `card_save` | 카드 저장 | `{"card_id": 123}` |
| `revisit` | 세션 있는 상태로 재접속 | — |

payload에 허용된 키(`tab`, `market`, `stock_code`, `card_id`, `from_tab`, `to_tab`, `is_default`) 외에는 저장되지 않는다 — 개인정보·금액 정보는 구조적으로 수집 불가(F-8.6).
