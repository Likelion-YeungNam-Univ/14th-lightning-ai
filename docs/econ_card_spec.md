# assit 경제 상식 카드 기능명세서

팀 번개조 | 2026.08 | 기준 문서: `assit 요구사항명세서 v3` 기능 ID 체계 `[E-n.n.n]` — 기존 `[F-]` `[C-]`와 구분

---

## 0\. 이 기능이 무엇인가

홈 최상단, **국내/해외 구분 위에 경제 상식 카드 10장이 가로로 무한 순환**합니다. 카드를 탭하면 그 주제를 자세히 풀어주는 모달이 열립니다.

**LLM이 주제 선정부터 자료 조사, 집필, 제목 작성까지 전부 수행합니다.** 사람이 주제를 정해주지 않습니다. **2시간마다 10장이 새로 교체**됩니다.

**왜 필요한가** — 우리 서비스는 원자료를 초보의 말로 풀어주지만, `유상증자` `기준금리` 같은 개념을 **모르는 상태로는 요약을 읽어도 남지 않습니다.** 용어 풀이(F-5.4)는 사용자가 드래그해야 작동하는 수동 장치라, **묻지 않는 사람에게는 아무 일도 일어나지 않습니다.** 이 카드가 그 빈자리를 메웁니다.

---

## 1\. 확정 사항

착수를 막는 블로커는 없습니다. 세 항목을 아래와 같이 확정했습니다.

| \# | 항목 | 결정 |
| :---- | :---- | :---- |
| E-D1 | **검색 수단** | LLM API의 **웹 검색 도구를 그대로 쓴다.** 별도 검색 API를 계약하지 않는다 (E-2.1a) |
| E-D2 | **허용 도메인** | **부록 1 목록으로 확정.** 목록 밖 출처는 자동 반려 (E-3.1.2) |
| E-D3 | **검수 표본 비율** | **10%, 최소 2건.** 표본에서 오류가 나오면 배치 전체 반려 (E-3.2) |

## 2\. 먼저 짚어둘 설계 위험 네 가지

### 2-1. 「알아서 찾아서 쓰기」는 도구가 있어야 성립합니다

사람에게 "공식 자료만 찾아서 풀어써 달라"고 하면 검색을 해서 원문을 읽고 씁니다. **LLM도 같은 일을 하지만, 검색 도구가 붙어 있어야 합니다.** 도구 없이 같은 지시를 하면 학습된 기억으로 쓰면서 "찾아봤다"고 말합니다. 그게 가장 위험한 상태입니다.

**그래서 검색 도구 연동이 이 기능의 전제 조건입니다.** 이미 쓰고 있는 LLM API의 도구를 켜는 것으로 해결됩니다(E-2.1a). 검색 없이 착수하면 근거 없는 글이 나옵니다.

### 2-2. 「공식 자료 위주」는 목록으로 정의해야 합니다

`공식 자료 위주로 써라`는 지시만으로는 통제되지 않습니다. LLM이 블로그를 공식 자료로 판단할 수 있고, 그러면 **원자료를 읽게 만든다는 서비스 전제가 카드에서부터 무너집니다.**

**허용 도메인 목록으로 제한합니다**(부록 1, 확정). 금지 목록 방식은 새 사이트가 계속 생겨 막을 수 없습니다.

### 2-3. 생성량과 검수량을 분리합니다

카드는 **소모되지 않습니다.** 승인 풀에 120건이 쌓이면 그다음부터는 회전만 돌면 됩니다. 매일 120건을 새로 만들 필요가 없습니다.

|  | 초기 적재 | 이후 운영 |
| :---- | :---- | :---- |
| 생성 | **120건 한 번에** | 하루 5\~10건 보충 |
| 목적 | 첫날부터 풀을 채운다 | 낡은 카드 교체 |

**검수는 자동 필터 \+ 사람 표본 두 단계입니다.**

| 단계 | 무엇을 | 누가 |
| :---- | :---- | :---- |
| 1차 | 출처 URL 없음 · 허용 도메인 밖 · 수치 포함 · 금지 표현 | **시스템이 자동 반려** |
| 2차 | 통과한 카드 중 **표본 10%** 의 내용 정확성 | 사람 |

**1차가 실질적인 방어선입니다.** URL이 없으면 검색을 하지 않고 쓴 것이므로 내용을 볼 필요도 없이 거릅니다. 120건 중 자동 필터를 통과한 것 가운데 12건만 사람이 보면 되고, **표본에서 오류가 나오면 그 배치 전체를 반려**합니다.

### 2-4. 무한 스크롤에는 정지 조건이 필요합니다

계속 움직이면 **읽는 중에 글자가 화면을 벗어나고**, 탭하려면 움직이는 카드를 맞춰 눌러야 합니다.

- **마우스를 올리면 정지**한다(E-1.4)  
- 모바일에서는 자동 이동을 끄고 **손가락 스와이프**로만 움직인다  
- `prefers-reduced-motion`이 켜져 있으면 애니메이션을 끈다

| :---- | :---- | :---- | :---- | :---- |
| **\[E-1.1\] 위치** | 홈 최상단 |  | 상단바 아래, **국내/해외 구분 위**. 구분·종목·탭 선택과 무관하게 **항상 같은 자리**에 있는다 | 상 |

| **\[E-1.2\] 카드 규격** | 4열 그리드 기준 |  | 카드 **315×200**, 간격 28\. **이미지 영역을 두지 않는다.** 화면에 4장이 보이고 나머지는 잘린다 | 상 |
| **\[E-1.3\] 가로 무한 순환** | 마퀴 |  | 10장이 **왼쪽으로 계속 흘러간다.** 끝에 닿으면 처음 카드가 이어져 끊김이 없다 — 트랙에 10장을 **두 벌 이어 붙이고**, 한 벌 폭만큼 이동한 뒤 위치를 0으로 되돌린다 | 상 |
| \[E-1.3.1\] 이동 속도 | 읽을 수 있는 속도 | 확정 필요 | (제안) 카드 한 장이 지나는 데 **6\~8초**. 너무 빠르면 제목을 못 읽고, 느리면 멈춘 것처럼 보인다 | 상 |
| \[E-1.3.2\] 좌우 페이드 | 잘린 카드 처리 |  | 뷰포트 좌우 끝에 배경색 그라디언트를 겹쳐, 카드가 **잘리는 게 아니라 흘러 들어오는 것**처럼 보이게 한다. 오른쪽 120px, 왼쪽 60px | 중 |
| **\[E-1.4\] 정지 조건** | 사용성 |  | **마우스를 올리면 멈춘다.** 모바일에서는 자동 이동을 끄고 스와이프로만 움직인다. `prefers-reduced-motion`이 켜져 있으면 애니메이션을 끈다 | 상 |
| \[E-1.5\] 로딩 상태 | 생성 지연 대비 |  | 카드는 **미리 승인된 것을 읽어온다**(E-5). 사용자 요청 시점에 LLM을 호출하지 않는다 | 상 |
| \[E-1.6\] 실패 상태 | 카드 없음 |  | 조회 실패 시 **영역을 접는다.** 빈 회색 박스를 남기지 않는다. 없어도 서비스가 동작해야 한다 | 상 |

│                     │

**카드에는 질문 제목만 둡니다.** 이미지·아이콘·카테고리 라벨·부제를 넣지 않습니다.

- **이미지를 넣지 않는 이유** — 주제를 LLM이 자유롭게 잡으므로 **어떤 그림이 맞는지 미리 알 수 없습니다.** 아이콘 세트를 정해두면 그 분류에 맞는 주제만 나와야 하고, 결국 라벨을 두는 것과 같아집니다  
- **라벨을 넣지 않는 이유** — 주제 분류를 미리 정해야 하고, 그러면 LLM이 자유롭게 주제를 잡을 수 없습니다

**카드 규격** — 315×200, 간격 28\. 이미지 영역이 없어 이전 안(334)보다 낮습니다. 종목 줄과 탭 줄이 화면 위쪽에 그대로 남습니다.

**섹션 라벨** — `알아두면 좋은 경제 상식` \+ `1시간마다 10개가 새로 올라와요 · 왼쪽으로 계속 흘러가고, 마우스를 올리면 멈춰요`

# E-2. 콘텐츠 생성 — LLM 자율 수행

**LLM에게 맡기는 일의 순서**

① 주제 선정      초보 투자자에게 필요한 개념을 스스로 고른다

② 자료 조사      허용 도메인에서 공식 자료를 검색해 읽는다

③ 집필          찾은 자료를 근거로 초보 언어로 풀어 쓴다

④ 제목 작성      쓴 내용의 제목을 질문 형태로 뽑는다

⑤ 출처 반환      근거로 쓴 URL을 함께 돌려준다

| 페이지 | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| **\[E-2.1\] 생성 방식** | 배치 \+ 승인 풀 |  | 사용자 요청 시점에 생성하지 않는다. **배치가 카드를 만들어 승인 풀에 쌓고, 화면은 풀에서 10장을 뽑아 보여준다**(E-5) | 상 |
| **\[E-2.1a\] 웹 검색 도구** | 자료 조사 수단 |  | **요약 생성에 쓰는 LLM API의 웹 검색 도구를 그대로 쓴다.** 별도 검색 API(Tavily·Brave 등)를 계약하지 않는다 — 이미 붙어 있는 API에 도구 하나를 켜는 일이다 | 상 |
| \[E-2.1a-1\] 도구 없이 쓰면 안 되는 이유 | 설계 근거 |  | 도구 없이 "공식 자료를 찾아 써라"고 지시하면 **학습된 기억으로 쓰면서 찾아본 것처럼 답한다.** 이 실패는 내용으로는 잡히지 않고 출처 URL 유무로만 잡힌다(E-3.1.1) | — |
| \[E-2.1a-2\] 검색 횟수 제한 | 비용 통제 |  | 카드 한 건당 검색 **최대 5회**. 넘으면 생성을 중단하고 그 건을 버린다. 주제를 못 찾아 헤매는 경우를 끊는다 | 중 |
| **\[E-2.2\] 주제 선정** | LLM 자율 |  | **주제를 지정하지 않는다.** 프롬프트로 방향만 준다 — `투자를 시작한 20대가 알아두면 좋은 경제·금융 개념 하나를 골라라`. 부록 2의 목록은 **예시이며 제약이 아니다** | 상 |
| \[E-2.2.1\] 중복 회피 | 같은 주제 반복 |  | **최근 승인된 카드 제목 목록을 프롬프트에 넣어** 같은 주제를 피하게 한다. 승인 단계에서 중복이면 반려한다 | 상 |
| \[E-2.2.2\] 주제 방향 | 서비스와 연결 |  | 프롬프트에 **우리가 다루는 세 축(공시·금리·규제)에서 나오는 개념을 우선하라**고 지시한다. 카드에서 배운 개념을 그날 요약 시트에서 다시 만나야 학습이 붙는다 | 상 |
| **\[E-2.3\] 자료 출처 제한** | 공식 자료만 |  | **허용 도메인 목록(부록 1\) 안에서만 검색한다.** 목록 밖 페이지를 근거로 썼으면 후처리에서 반려한다. 블로그·커뮤니티·개인 채널·위키는 금지 | 상 |
| \[E-2.3.1\] 출처 반환 의무 | 검증 가능성 |  | **근거로 쓴 URL을 1\~3개 함께 반환한다.** URL이 없는 생성물은 자동 반려한다 — 검색을 하지 않고 쓴 것이다 | 상 |
| \[E-2.3.2\] 출처 노출 | 모달 하단 |  | 모달 하단에 출처 링크를 노출한다. 사용자가 원문으로 갈 수 있어야 한다 | 상 |
| **\[E-2.4\] 출력 구조** | 카드 \+ 모달 |  | 한 번의 작업으로 **`title`(질문형 한 줄)** · **`body`(모달 본문)** · **`source_url`(1\~3개)** · **`target_tab`** 을 반환한다 | 상 |
| \[E-2.4.1\] 제목은 질문형 | 카드 노출 문구 |  | **본문을 먼저 쓰고, 그 내용의 제목을 질문 형태로 뽑는다.** 서술형(`기준금리란`)보다 탭 유인이 크다. 40자 이내, 물음표로 끝난다 | 상 |
| \[E-2.4.2\] 본문 구조 미강제 | 자유 단락 |  | 단락 수와 순서를 정해두지 않는다. **개념에 따라 필요한 만큼 쓴다.** 다만 마지막 단락에서 **assit의 어느 탭에서 이 개념을 만나는지** 안내한다 — 이 한 단락이 카드와 서비스 본체를 잇는다 | 상 |
| \[E-2.5\] 문체 | 초보 기준 |  | 기존 요약과 같은 문체 — `~예요` `~해요`. 전문 용어는 괄호로 풀어준다 | 상 |
| \[E-2.6\] 길이 | 읽는 부담 |  | 카드 제목 **40자 이내**, 모달 본문 **단락당 3\~4문장**. 길면 안 읽는다 | 중 |

# E-3. 검증 — 자동 필터 \+ 사람 표본

| 페이지 | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| **\[E-3.1\] 자동 반려 조건** | 1차 필터 |  | 아래 중 하나라도 걸리면 **사람이 보기 전에 반려**한다. 내용을 읽을 필요가 없다 | 상 |
| \[E-3.1.1\] 출처 없음 | 검색 미수행 |  | `source_url`이 비어 있으면 반려. **검색을 하지 않고 학습된 기억으로 쓴 것이다** | 상 |
| \[E-3.1.2\] 허용 도메인 밖 | 출처 부적격 |  | `source_url`의 도메인이 허용 목록(부록 1)에 없으면 반려 | 상 |
| \[E-3.1.3\] 수치 포함 | 낡은 정보 차단 |  | 본문에 숫자 토큰이 있으면 반려. 검색으로 `기준금리 2.75%`를 확인했더라도 쓰지 않는다 — **카드는 풀에 몇 주씩 머물러, 값이 바뀌면 틀린 카드가 계속 돌아간다** | 상 |
| \[E-3.1.4\] 단정 표현 | 인과 과장 |  | `~하면 반드시 ~한다` 패턴을 검출해 반려한다. `대개` `~인 경우가 많아요` 같은 완화 표현을 쓰게 한다 | 상 |
| \[E-3.1.5\] 금지 표현 | 투자자문 경계 |  | 기존 출력 가드레일(F-5.5) 적용 — 매수·매도 권유, 목표가·상승률 단정, 미래 방향 예측 | 상 |
| \[E-3.1.6\] 링크 생존 확인 | 실재 여부 |  | `source_url`에 HEAD 요청을 보내 200이 아니면 반려한다. **없는 URL을 지어낸 경우를 잡는다** | 상 |
| **\[E-3.2\] 사람 표본 검수** | 2차 확인 |  | 자동 필터를 통과한 카드 중 **10%, 최소 2건**을 사람이 확인한다. 링크를 열어 내용이 맞는지 대조한다. 배치가 20건 미만이어도 2건은 본다 | 상 |
| \[E-3.2.1\] 표본 실패 처리 | 배치 단위 반려 |  | **표본에서 오류가 나오면 그 배치 전체를 반려**한다. 같은 프롬프트로 만든 것이라 같은 문제가 있을 가능성이 높다 | 상 |
| \[E-3.2.2\] 검수 항목 | 무엇을 보는가 |  | ① 링크를 열어 내용이 맞는가 ② 원문에 없는 인과를 덧붙이지 않았는가. **①②만 본다 — 나머지는 자동 필터가 이미 걸렀다** | 상 |
| \[E-3.3\] 잠금 | 검수본 보호 |  | 승인된 카드는 잠근다. 재생성으로 덮이면 검수가 무의미해진다 | 상 |
| \[E-3.4\] 오류 신고 | 사후 대응 | 방식 미정 | 사용자가 카드 내용의 오류를 신고할 경로를 둔다. 신고된 카드는 **즉시 회전에서 제외**하고 재검수한다 | 중 |

**자동 필터가 왜 실질적인 방어선인가** — 이 기능에서 가장 위험한 실패는 **LLM이 검색하지 않고 아는 대로 쓰면서 찾아본 것처럼 답하는 것**입니다. 그건 내용을 읽어서 잡는 게 아니라 **URL 유무와 링크 생존으로 잡습니다.** 사람이 볼 것은 "링크 내용과 글이 맞는가" 하나만 남습니다.

# E-4. 상세 모달

| 페이지 | 기능 | 질문 | 세부 사항 | 우선순위 |

| **\[E-4.1\] 모달 열기** | 카드 탭 |  | 카드를 탭하면 모달이 열린다. 별도 페이지로 이동하지 않는다 — 홈 위에 뜨는 창 원칙(PRD)을 따른다 | 상 |
| \[E-4.2\] 구성 | 위에서 아래로 |  | `질문 제목` → `본문` → `드래그 안내` → `탭 바로가기` → **`출처 링크`** → `생성물 표기`. **주제 배지를 두지 않는다** | 상 |
| \[E-4.3\] 용어 드래그 | 확장 학습 |  | **본문에서 단어를 드래그하면 용어 풀이 팝오버(F-5.4)가 뜬다.** 칩을 미리 두지 않는다 — 무엇이 어려운지는 사람마다 다르고, 미리 고른 2\~3개가 그 사람이 막힌 단어일 확률은 낮다. 하단에 `모르는 단어를 드래그하면 뜻을 알려드려요` 안내를 둔다 | 중 |
| **\[E-4.4\] 탭 바로가기** | 자료로 연결 |  | 본문 3단락에서 언급한 탭으로 이동하는 버튼. `한국은행 탭에서 보기` 형태. **이 버튼이 카드와 서비스 본체를 잇는 유일한 장치다** | 상 |
| \[E-4.5\] 저장 | 다시 보기 | 범위 확정 필요 | (제안) **범위 밖.** 즐겨찾기는 원자료 카드를 모으는 곳이라, 상식 카드가 섞이면 성격이 흐려진다 | 하 |
| \[E-4.4a\] 용어 풀이 캐시 키 | 문맥 구분 |  | 용어 풀이 캐시 키는 `용어 + 탭`인데(F-5.4), **상식 카드는 탭에 속하지 않는다.** 키에 `econ`을 쓰거나 카드 ID를 넣어 요약 시트의 캐시와 섞이지 않게 한다 | 중 |
| \[E-4.6\] 출처 표기 | 생성물 명시 |  | 모달 하단에 **`assit이 정리한 설명이에요. 기관 발표 자료가 아니에요.`** 를 표기한다. 다른 카드는 모두 원자료 출처가 있어 사용자가 같은 것으로 오해할 수 있다 | 상 |

# E-5. 갱신과 캐시

| 페이지 | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| **\[E-5.1\] 승인 풀 운영** | 사전 생성 방식 |  | 배치가 카드를 만들어 검수를 거쳐 **승인 풀**에 쌓는다. 목표 **120건 이상** — 하루 12세트가 돌아가므로 이 정도면 하루 안에 같은 카드를 두 번 볼 확률이 낮다 | 상 |
| **\[E-5.2\] 2시간 회전** | 노출 카드 교체 |  | **2시간마다(짝수 시 정각) 승인 풀에서 10장을 무작위로 뽑아 노출 세트를 교체**한다. 전역 공용이라 모든 사용자가 같은 세트를 본다 | 상 |
| \[E-5.2.1\] 직전 세트 회피 | 반복 인상 차단 |  | 직전 세트에 있던 카드는 새 세트에서 제외한다. 100건 풀이면 여유가 충분하다 | 중 |
| \[E-5.2.2\] 풀 부족 대응 | 10건 미만 |  | 승인 카드가 10건 미만이면 **있는 만큼만 노출**하고 순환을 그대로 돌린다. 미승인 카드로 채우지 않는다 | 상 |
| **\[E-5.3\] 초기 적재** | 첫 풀 확보 |  | **120건을 한 번에 생성**해 자동 필터를 통과시키고, 표본 10%(약 12건)를 사람이 확인한다. 6명이 2건씩이면 한 시간 안에 끝난다 | 상 |
| \[E-5.3a\] 이후 보충 | 낡은 카드 교체 |  | 하루 5\~10건 보충. **매일 120건을 새로 만들지 않는다** — 카드는 소모되지 않는다 | 상 |
| \[E-5.4\] 캐시 | 조회 부담 |  | 노출 세트는 캐시에서 읽고 **2시간마다만 무효화**한다. 사용자 수와 무관하게 조회 비용이 고정된다 | 상 |
| \[E-5.5\] 시연 대비 | 사전 적재 |  | **시연 전에 승인 카드를 최소 30건 쌓아둔다.** 10장 세트가 세 번은 다르게 나와야 회전이 보인다 | 상 |
| \[E-5.6\] 노출 자격 | 승인만 노출 |  | 회전 대상은 `status = approved`인 카드뿐이다. **자동 필터만 통과한 카드(`filtered`)는 노출하지 않는다** — 표본 검수 대상으로만 대기한다 | 상 |

# E-6. 데이터 모델

| 테이블 | 주요 컬럼 |
| :---- | :---- |
| `econ_card` | id, title, body, target\_tab, **source\_url(json)**, batch\_id, status(**draft/filtered/approved/rejected**), reject\_reason, locked, approved\_by, approved\_at, created\_at |
| `econ_rotation` | id, rotated\_at, card\_ids(json) — 매시 노출 세트 기록. 직전 세트 회피(E-5.2.1)에 쓴다 |

`econ_card`에 **`status`와 `locked`가 반드시 필요합니다.** 검수 절차(E-3.3)가 이 두 컬럼으로 동작합니다.

`source_url`이 **없는 카드는 자동 반려**됩니다(E-3.1.1). 검색을 하지 않고 쓴 것이기 때문입니다.

`status`가 네 단계입니다 — `draft`(생성 직후) → `filtered`(자동 필터 통과) → `approved`(표본 검수 또는 배치 승인) → `rejected`. **노출은 `approved`만** 합니다(E-5.6).

`batch_id`로 배치 단위 반려(E-3.2.1)를 처리합니다. `reject_reason`에는 어느 필터에 걸렸는지 남겨, 프롬프트를 고칠 근거로 씁니다.

**주제 테이블을 두지 않습니다.** LLM이 주제를 직접 잡으므로 사전 목록을 관리할 필요가 없고, 중복은 승인 단계에서 걸러냅니다. `target_tab`은 모달의 탭 바로가기 버튼에 씁니다.

## 부록 3\. 용어 풀이(F-5.4)와의 차이

같은 「개념을 설명한다」는 기능이라 겹쳐 보이지만 역할이 다릅니다.

|  | 용어 풀이 | 경제 상식 카드 |
| :---- | :---- | :---- |
| 시작 | 사용자가 **드래그해야** 작동 | **가만히 있어도** 보인다 |
| 범위 | 그 자료의 문맥에 한정 | 개념 자체 |
| 위치 | 요약 시트 안 | 홈 최상단 |
| 생성 | 요청 시점 · 사용자별 | 배치 · 전역 공용 |
| 검수 | 없음 (문맥이 근거) | **사람 승인 필수** |

**두 기능이 이어지는 지점** — 상식 카드 모달 본문에서도 **드래그로 용어 풀이를 호출**합니다(E-4.3). 요약 시트와 같은 팝오버 컴포넌트를 그대로 쓰므로 새로 만들 것이 없고, 사용자는 두 화면에서 같은 동작을 익힙니다.
