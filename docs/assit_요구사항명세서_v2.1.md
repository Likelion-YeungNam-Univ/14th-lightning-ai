# F-1. 계정 · 세션

> 로그인은 첫 관문이 아니다. 비로그인으로 다섯 탭을 모두 열람하고, **종목 추가**와 **카드 저장** 두 지점에서만 로그인을 요구한다.
>
> **실제 인증은 구현하지 않는다.** 사전 설정한 계정 하나를 입력하면 로그인된 것으로 처리하는 시연용 모의 구현이다.
>
> **데이터는 계정이 아니라 세션에 귀속시킨다.** 계정이 하나뿐이라 계정에 데이터를 붙이면 시연 중 여러 사람이 서로의 종목을 보게 된다.

| 기능 ID | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| **\[F-1.1\] 세션 발급** | 사용자 상태 보관 |  | 첫 진입 시 세션 식별자를 발급하고 쿠키에 저장한다. **보관 기간 30일 (확정).** 이 세션에 기본 종목 4개를 프로비저닝한다(F-2.8). 등록 종목과 저장 카드는 로그인 여부와 무관하게 이 세션에 귀속된다 | 상 |
| **\[F-1.2\] 모의 로그인** | 사전 설정 계정으로 로그인 처리 | 시연용 계정 값 확정 필요 (팀 결정, 개발 비의존) | 입력값이 사전 설정 계정과 일치하면 세션에 `authenticated = true`를 세운다. **계정 값은 저장소에 커밋하지 않고 환경 변수로 주입.** 가입·중복 확인·이메일 인증·비밀번호 재설정·로그아웃은 만들지 않는다 | 상 |
| \[F-1.3\] 로그인 요구 지점 | 종목 추가·카드 저장 시 인증 확인 |  | `authenticated`가 아니면 401\. **이 두 곳 외의 엔드포인트는 인증을 보지 않는다.** 로그인 창은 프론트 책임 | 상 |
| \[F-1.4\] 진행 중 행동 이어가기 | 로그인 후 원래 행동 완료 |  | 데이터가 세션에 그대로 있으므로 이관은 불필요하다. 프론트가 401 이전 요청을 재전송하면 된다. 백엔드에서 별도 상태 저장은 하지 않는다. **주: PRD 부록 B의 "로그인 시 상태를 계정으로 이관"과 의도적으로 다르다(C10).** PRD는 실서비스 기준 서술이고, 시연 범위(단일 모의 계정)에서는 세션 귀속이 정답이다. 사용자 관점 결과("로그인해도 방금 한 일이 사라지지 않는다")는 동일하다 | 상 |
| \[F-1.5\] 데모 데이터 초기화 | 시연 전 세션 상태 되돌리기 |  | 세션의 종목·저장 카드를 지우고 기본 종목 4개로 되돌린다. **노출 방식 (확정): `POST /admin/reset-demo` + 요청 헤더의 관리자 토큰(환경 변수 `ADMIN_TOKEN`) 검사(C5).** 토큰 불일치 시 401. 리허설을 반복하면 첫 진입 화면을 재현할 수 없으므로 반드시 필요하다 | 중 |

# F-3. 외부 데이터 수집

> 전 탭 **1일 1회 배치**. 종목을 새로 추가하면 그 종목만 즉시 1회 수집. **사용자 요청 경로에서 외부 API를 직접 부르지 않는다.**
>
> **(C9) 수집 단위는 세션이 아니라 "등록된 고유 종목"이다.** 여러 세션이 같은 종목을 등록해도 수집·생성은 종목당 1회만 수행하고 결과를 공유한다.

| 기능 ID | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| **\[F-3.1\] 공시 수집 (DART)** | 종목별 최근 공시 적재 |  | `corp_code` 기준 공시검색. **(확정) 대상 유형: 전체 공시 유형**(정기·주요사항·발행 등 필터 없이 최신순 — 유형 선별은 후순위). 적재: 접수번호, **공시 제목(원문 그대로)**, 공시 유형, 제출일, 원문 링크. 최근 3개월, 종목당 최신 20건. 원본파일 파싱은 범위 밖 | 상 |

# F-4. AI 가공

> LLM은 Claude API(`claude-opus-5`)를 기본으로 사용한다. 모든 생성은 배치·온디맨드 수집 직후 1회 수행 후 DB에 저장해 재사용한다 — **사용자 요청 경로에서 LLM을 호출하는 기능은 용어 풀이(F-4.4) 하나뿐이다.**

| 기능 ID | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| **\[F-4.1\] 카드 요약 생성** | 원자료를 쉬운 말로 |  | 대상: 공시·규제·한국은행·Fed (**유튜브 제외 — 요약 없음**). 입력 범위가 탭마다 고정: 공시는 제목+공시 유형까지, 규제는 API 본문, 금리는 지표 값과 결정 요지. **(C8) 공시 요약 시 공시 유형 해설을 지식베이스(F-4.8)에서 검색해 컨텍스트로 주입한다.** 다른 탭 자료, 특히 유튜브 내용을 입력에 섞지 않는다. 자료 단위로 1회 생성 후 재사용 | 상 |
| **\[F-4.1.1\] 요약 2단 생성** | 목록용과 시트용 |  | **(확정) `summary_short`(두세 줄)와 `summary_full`(전문)을 한 번의 호출로 함께 생성**(structured output으로 두 필드 스키마 강제). 전문을 글자 수로 자르면 문장 중간에서 끊겨 목록 카드가 미완성 문장이 된다 | 상 |
| **\[F-4.1.2\] 제목 미가공** | 원문 제목 보존 |  | **제목은 LLM 출력 대상이 아니다.** 원문 제목을 그대로 저장·반환한다. 요약 생성 시 입력으로는 쓰되 제목 필드를 생성하지 않는다 | 상 |
| \[F-4.1.3\] 공시 요약 제약 | 없는 정보 생성 차단 |  | **제목에 없는 금액·수량·계약 상대방·조건을 생성하지 않는다.** 후처리 (확정): 생성물의 **금액·수량형 숫자 토큰**(원·주·%·배 단위 동반 숫자)이 입력(제목+유형 해설)에 없으면 해당 필드 재생성, 재위반 시 비움. 연도·일자 등 날짜형 숫자는 검사 제외 | 상 |
| **\[F-4.2\] 영향 라벨 생성** | 긍정/중립/부정 \+ 판단 이유 |  | 부착: 공시·규제 동향. 미부착: 유튜브·한국은행·Fed. 규칙: 퍼센트 미표기 / **판단 이유 필수 동반** / 애매하면 중립 / 정렬·집계 기준으로 쓰지 않음. **(확정, C4) 검증 절차: 시연 종목은 라벨·이유 전수 검수 후 잠금(F-4.7), 비시연 종목은 탭별 10% 표본 검수. 오판 발견 시 해당 자료 재생성 또는 중립 강제** | 상 |
| \[F-4.2.1\] 생성 단위 | 조합 폭발 방지 |  | 공시 \= **자료 1건 × 종목 1개**. 규제 \= **자료 1건 × 업종 1개**. 규제 라벨은 업종 단위로 한 번 만들어 공유한다. 생성량이 종목 수가 아니라 업종 수로 고정된다 | 상 |
| \[F-4.2.2\] 라벨 오용 차단 | 매수 신호화 방지 |  | **응답 스키마에 라벨 카운트·비율 필드를 만들지 않는다.** 정렬 파라미터로 라벨 값을 받지 않는다 | 상 |
| **\[F-4.3\] "내 종목엔" 문장** | 금리 지표를 업종에 잇는 한두 줄 |  | 대상: 한국은행·Fed 탭만, **목록 위에 1회**(카드마다 아님). **(C7) 입력: `industry_profile`의 업종 성격 서술 \+ 금리 지표 \+ 최근 변동 방향.** 금지: 방향 예측, 매수·매도 시사, 수치 단정. 조건을 만족하지 못하면 빈 값을 반환하고 카드만 노출한다 | 상 |
| \[F-4.3.1\] 종목명 미사용 검증 | 정밀도 오인 차단 |  | 문장은 업종 단위이므로 **종목명을 부르지 않는다.** 생성물에 종목명 문자열이 있으면 재생성하거나 비운다 | 상 |
| \[F-4.3.2\] 문장 캐싱 | 표현 흔들림 방지 |  | **(C11) 캐시 키 `탭(한국은행/Fed) + 업종 + 지표 스냅샷`.** 지표 갱신 시에만 무효화 | 상 |
| \[F-4.4\] 용어 풀이 | 드래그한 단어를 문맥 기준 설명 |  | **호출 지점은 요약 시트다.** 입력: 드래그 텍스트(**상한 50자, 확정**) \+ 해당 자료의 요약 본문 \+ **(C8) 지식베이스(F-4.8)에서 검색한 관련 용어 정의 top-3 (RAG)**. 출력: 한두 줄 정의. **정의까지만 하고 영향 판단은 하지 않는다.** 캐시 키 `용어 + 탭` (확정 — 같은 탭의 같은 용어는 설명 공유. 카드별 문맥 차이보다 응답 속도·비용 우위). **응답 속도 대책 (확정): 캐시 우선 조회 → 미스 시 경량 프롬프트 단일 호출, 스트리밍 응답** | 중 |
| \[F-4.5\] 출력 가드레일 | 금지 표현 차단 |  | 생성물 전체 공통 후처리. 차단: 매수·매도 권유, 목표가·상승률 등 수치 단정, 미래 방향 예측. **위반 시 재생성 1회, 그래도 위반이면 필드를 비운다** | 상 |
| \[F-4.6\] 생성물 무효화 | 원자료 갱신 시 재생성 |  | 원자료가 바뀌면 딸린 생성물을 무효화. **저장된 카드의 스냅샷은 건드리지 않는다** | 중 |
| \[F-4.7\] 검수 잠금 | 시연 종목 생성물 고정 | 검수 대상 종목 목록 확정 필요 (시연 시나리오와 함께 결정) | `locked` 플래그로 잠글 수 있어야 한다. 재생성으로 덮이면 검수가 무의미해진다 | 중 |
| **\[F-4.8\] 금융 용어 지식베이스 (RAG, 신설 C8)** | 생성 근거 검색 |  | **적재 소스: ① 한국은행 「경제금융용어 700선」(공개 자료, 용어·정의 단위로 청킹) ② DART 주요 공시 유형 해설(유상증자·단일판매공급계약·유형자산취득 등 20\~30건, 팀 작성 또는 공개 해설 정리).** 각 청크를 임베딩해 pgvector에 저장. 검색: 질의 임베딩 → 코사인 유사도 top-k(k=3). 사용처: F-4.4 용어 풀이(질의=드래그 텍스트), F-4.1 공시 요약(질의=공시 유형·제목). **유사도 하한 미달 시 컨텍스트 없이 생성**(억지 주입 금지). 적재는 1회성 스크립트, 갱신 없음 | 상 |

# F-5. 콘텐츠 조회

> **카드 목록과 요약 시트는 같은 데이터를 쓴다.** 목록 조회 시 시트에 필요한 필드까지 함께 내려보내고, 시트를 열 때 추가 호출을 하지 않는다. 탭당 자료 건수가 20건 내외라 페이로드 부담이 작다.

| 기능 ID | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| **\[F-5.1\] 카드 목록 조회** | 탭 × 종목 조합의 카드 반환 |  | 파라미터 `tab`, `stock_code`. **(확정, C12) 페이지네이션 없음 — 탭당 최신 20건 고정.** 응답 스키마는 다섯 탭이 공통이며 없는 요소는 `null`로 둔다(F-5.1.1). 비로그인도 호출 가능 — `is_saved`만 `false` 고정 | 상 |
| **\[F-5.1.1\] 공통 카드 스키마** | 탭별 분기 최소화 |  | 필드: **`card_id`(C6 — 저장 API가 이 값을 받는다)**, `label`, `label_reason`, `title`(원문), `summary_short`, `summary_full`, `source_name`, `published_at`, `origin_url`, `is_saved`, `thumbnail_url`, `channel_name`, `view_count`, `indicator_value`. **탭별로 필드를 빼지 말고 `null`로 채운다** — 프론트가 하나의 카드 컴포넌트로 렌더링하고 요소를 켜고 끈다 | 상 |
| \[F-5.1.2\] 탭별 채워지는 필드 | 무엇이 `null`인가 |  | 유튜브: `label`·`label_reason`·`summary_*`가 `null`, `thumbnail_url`·`channel_name`·`view_count` 채움. 공시·규제: 라벨과 요약 채움, 유튜브 필드 `null`. 한국은행·Fed: `label`·`label_reason` `null`, `indicator_value` 채움 | 상 |
| \[F-5.1.3\] 정렬 규칙 | 카드 나열 순서 |  | 기본 최신순, 유튜브만 조회수순. **라벨을 정렬 기준으로 제공하지 않는다** | 상 |
| \[F-5.2\] 금리 탭 연결 문장 | 목록 위 1회 노출 |  | 응답 최상단에 `link_sentence`(업종 단위). **문장이 비어 있어도 카드는 반환한다.** 지표 카드는 모든 종목 공통이므로 종목별로 다시 계산하지 않는다 | 상 |
| \[F-5.3\] 유튜브 목록 부가 정보 | 참고용 표시 근거 |  | 응답에 `disclaimer` 플래그를 포함해 프론트가 "참고용 · 개인 의견입니다"를 고정 노출할 근거를 준다. 시트가 없으므로 카드 탭은 외부 이동 | 상 |
| \[F-5.4\] 빈 상태 응답 | 자료 없음과 오류 구분 |  | 빈 배열 \+ 사유 코드: `no_data` / `fetch_failed`. 규제 동향 탭에서 실제로 자주 쓰인다 | 중 |
| \[F-5.5\] URL 상태 복원 | 탭·종목 조합 북마크 |  | **조회 API는 직전 조회 이력에 의존하지 않는다.** URL 파라미터만으로 화면이 복원되어야 하고 뒤로 가기가 동작해야 한다 | 중 |

# F-6. 카드 저장

| 기능 ID | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| \[F-6.1\] 카드 저장 | 카드를 저장됨에 담기 |  | 대상: **모든 탭의 모든 카드(유튜브 영상 포함).** 요청 바디: `card_id` \+ 저장 당시의 `tab`·`stock_code`(배지용, C6). 중복 저장은 멱등. 비로그인이면 401(F-1.3) | 상 |
| \[F-6.2\] 저장 해제 | 저장 취소 |  | 재클릭으로 해제. 스냅샷도 함께 삭제 | 상 |
| **\[F-6.3\] 저장 스냅샷** | 저장 시점 내용 고정 |  | **저장 시점의 제목·요약(단문·전문)·라벨·판단 이유·출처·날짜를 `snapshot_json`으로 복사해 보관한다.** 원자료가 갱신되거나 요약이 재생성되어도 저장본은 바뀌지 않는다. 원문 링크만 살아 있는 링크로 두고, 링크가 만료돼도 저장한 요약은 남는다. **원자료(`source_item`)가 3개월 롤링으로 삭제돼도 저장 카드는 남아야 하므로 FK는 nullable로 두고 표시엔 스냅샷만 쓴다.** **(C15) 유튜브 카드 예외: YouTube API 약관(메타데이터 30일 보관 제한)에 따라 스냅샷에 제목·원문 링크만 보관하고, 썸네일·조회수는 스냅샷에 넣지 않는다** | 상 |
| \[F-6.4\] 저장됨 목록 조회 | 저장한 카드 반환 |  | 최근 저장 순. 각 항목에 **저장 당시의 탭·종목을 배지용 필드로 반환.** 종목 줄이 필터로 동작하므로 `stock_code` 파라미터 지원 | 상 |

# F-7. 공통 · 비기능

| 기능 ID | 기능 | 질문 | 세부 사항 | 우선순위 |
| :---- | :---- | :---- | :---- | :---- |
| \[F-7.1\] 에러 응답 규격 | 오류 형식 통일 |  | 모든 에러는 `code`, `message`, `details`. 사용자 노출 문구는 프론트가 코드로 매핑 | 상 |
| **\[F-7.2\] 지표 이벤트 수집** | 부록 D 산출 |  | **(확정, C14) 자체 `event_log` 테이블에 적재.** 필수 이벤트: 홈 도달, 첫 종목 탭 진입, 탭별 진입, 유튜브 → 타 탭 이동, 요약 시트 열람, 시트 → 원문 이동, 종목 추가, 로그인 전환, 카드 저장, 재방문. **"재방문" 정의 (확정): 마지막 활동 24시간 이후의 세션 재진입.** 시트 열람과 원문 이동을 따로 잡아야 "목록에서 멈췄는가"와 "요약이 부족했는가"를 구분할 수 있다 | 중 |
| \[F-7.3\] 레이트리밋 | 남용·비용 방지 |  | LLM을 동반하는 엔드포인트(F-4.4)는 세션당 분당 20회 (확정) \+ IP 기준 제한 | 중 |
| \[F-7.4\] 시크릿 관리 | 인증키 보관 |  | ECOS·FRED·DART·YouTube 키 4종 \+ **LLM 키(Anthropic) \+ 임베딩 키(OpenAI 또는 Voyage, C8)** \+ 모의 로그인 계정 값 \+ **관리자 토큰(C5)**. 저장소에 커밋하지 않고 환경 변수로 주입 | 상 |
| \[F-7.5\] 캐시 계층 | 응답 속도·장애 격리 |  | 외부 API 응답과 LLM 생성물은 **DB 적재 자체가 캐시다**(별도 Redis 불요). 용어 풀이만 별도 캐시 테이블(`용어+탭` 키). 사용자 요청 경로에서 외부 API를 직접 호출하는 구간을 만들지 않는다 | 상 |
| \[F-7.6\] 개인정보 최소 수집 | 수집 항목 제한 |  | **평단가·수량 등 금액 정보는 어떤 경로로도 받지 않는다.** 스키마에 컬럼을 만들지 않는 것으로 고정 | 상 |
| **\[F-7.7\] 배포 전제 (신설 C13)** | 세션 쿠키 동작 보장 |  | 프론트(Vercel)와 백엔드가 다른 도메인이면 쿠키에 `SameSite=None; Secure` \+ CORS `allow-credentials` 필요. **권장: 프론트에서 `/api/*` rewrite 프록시로 백엔드를 동일 출처화**하면 쿠키 문제가 사라진다. 또한 APScheduler가 프로세스 내에서 돌므로 **백엔드 워커는 1개로 고정**(다중 워커 시 배치 중복 실행) | 상 |
