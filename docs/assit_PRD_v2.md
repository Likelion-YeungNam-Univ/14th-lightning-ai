## 1\. 개요

### 1.1 한 줄 정의

> 경제 뉴스를 접한 20대 초보 투자자가, **내 종목에 걸리는 정보를 출처별로 한 화면에서 확인하고 각 정보가 내 종목에 어떤 의미인지 이해**할 수 있게 하는 서비스.

`asset + insight = assit`

### 1.2 제품 목표

**해결하려는 핵심 문제** 내 종목에 걸리는 자료가 어디에 있는지 몰라 흩어진 채널을 반복 탐색하고, 찾아낸 원자료(공시·금통위 결정문·부처 발표)는 용어가 어려워 읽어도 무슨 사안인지 파악되지 않는 상태.

**도달하고자 하는 상태**

| 현재 | 목표 |
| :---- | :---- |
| 어디서부터 찾아야 할지 몰라 채널을 옮겨 다님 | **무엇을 어디서 확인하는지가 다섯 개 출처 탭으로 제시됨** |
| 자료가 기관 사이트마다 흩어져 있음 | 한 종목을 고른 채로 탭만 옮기면 출처별 자료가 이어서 나옴 |
| 공시·결정문을 열어도 용어에 막혀 무슨 사안인지 모름 | 쉬운 말 요약이 붙어 **이 자료가 무슨 사안인지**까지는 파악됨 |
| 사안이 내 종목에 유리한지 불리한지 판단할 근거가 없음 | 공시·규제 카드에 방향 라벨과 판단 이유가, 금리 탭에는 업종 수준의 연결 문장이 붙음 |

**세 번째와 네 번째 줄의 수위가 다르다.** 요약은 개별 자료를 다루므로 종목 단위로 정확하지만, 방향 판단은 업종 수준의 일반적 관계까지만 말한다. 이 차이를 문서 전체에서 일관되게 지킨다.

**목표가 아닌 것**

- **투자 판단 대행** — 매수·매도를 권하지 않는다  
- **속보 전달** — 가장 빠른 뉴스를 주는 것이 목적이 아니다  
- **정보량 확대** — 더 많이 보여주는 것이 아니라 무엇을 봐야 하는지를 알려준다  
- **탐색 채널 전부의 대체** — 커뮤니티 여론과 차트·시세는 다루지 않는다. 반복 탐색 중 **공공 자료로 대체 가능한 부분**만 이 제품이 맡는다  
- **종목 단위 해석** — 거시 지표와 종목의 관계는 업종 성격에 근거한 일반론까지만 말한다. 특정 종목만을 분석한 결론은 내지 않는다

### 1.3 배경

**시장 환경**

- 청년층 투자 참여율이 2023년 27.6%에서 2025년 43.4%로 2년 새 15%p 증가 (대학내일20대연구소, 금융·재테크 정기조사 2025\)  
- 재테크 정보 획득 경로 1위는 뉴스·신문 기사 39.6% (Z세대 트렌드 리포트 2025\)  
- 20대의 41%가 경제·금융 뉴스를 이해하기 어렵다고 응답, 한국 평균 38%보다 높음 (한국언론진흥재단, 디지털 뉴스 리포트 2023\)  
- 20대 금융이해력 62.6점으로 2022년 대비 3.2점 하락, 성인 평균 65.7점 하회 (금융감독원, 2024 전국민 금융이해력 조사)

**경쟁 공백**

| 채널 | 제공하는 것 | 제공하지 못하는 것 |
| :---- | :---- | :---- |
| 뉴스 매체 | 사실 전달 | 내 종목과의 연결 |
| 유튜브·커뮤니티 | 해석과 의견 | 출처 검증, 일관된 구조 |
| 증권사 앱 | 시세, 보유 현황 | 거시·정책 정보의 해석 |
| 정부·기관 사이트 | 1차 자료 | 초보가 읽을 수 있는 형태 |

**마지막 행이 이 제품의 진입 지점이다.** 한국은행 금통위 결정문, DART 공시, 부처 보도자료는 모두 공개되어 있지만 초보 투자자가 찾아 읽고 자기 종목에 연결하기는 어렵다.

## 2\. 문제 및 해결 방안

### 2.1 사용자 문제

**언제** — 보유 종목에 관한 소식을 접했거나, 금리·정책 뉴스를 보고 내 종목이 걱정될 때

**무엇 때문에** — 어떤 정보를 어디서 확인해야 하는지 모르고, 찾더라도 그것이 자기 종목에 어떤 의미인지 연결하지 못해서

**어떤 불편함** — 확신을 얻으려 여러 채널을 탐색하지만 해석이 갈려 혼란이 커지고, 시간과 인지 부담만 쌓인다

**문제의 연쇄 구조**

뉴스의 원리를 모름

  → 방향은 알아도 확신이 안 섬

    → 확신을 얻으려 다른 채널을 탐색

      → 해석이 갈려 오히려 혼란 가중

        → 탐색 비용만 늘고 이해에는 도달하지 못함

**사용자 인터뷰 근거 (20대 초보 투자자 4명)**

| 병목 | 실제 발언 |
| :---- | :---- |
| 인과 이해 부족 | "'금리↑ → 위험자산↓' 정도는 알아요. 근데 유동성이 실제로 코인까지 흘러오는 중간 단계가 막혀요" |
| 인과 이해 부족 | "한은 총재 뉴스 때 이론은 잡혔는데 내가 아는 정보가 시장에 적용될지 모르겠어서 방향성을 잃었어요" |
| 탐색 피로 | "사람마다 해석이 다르니까 보면 볼수록 결정이 어려워져요" |
| 탐색 방향 부재 | "어디서부터 찾아야 하나요?" (어피니티) |

**앞의 두 발언이 이 구조의 직접 근거다.** 거시 정보에서 내 종목까지 내려오는 경로를 잇지 못하는 것이 핵심 병목이며, 다섯 탭 구조는 그 경로를 화면으로 드러낸다.

**고객 여정에서 이 제품이 담당하는 구간**

뉴스노출 → 영향 파악 시도 → **추가 탐색 → 정보 비교** → 판단 시도 → 의사결정 보류 → 사후 경험

앞의 네 단계까지가 담당 범위다. 판단 시도 이후 구간은 다루지 않으며, 문서와 발표에서도 해결했다고 주장하지 않는다.

### 2.2 해결 방안

**핵심 방식** — 화면은 위에서 아래로 **탭 → 종목 줄 → 콘텐츠** 세 층으로 구성한다. 위에서 출처를 고르고, 그 아래에서 종목을 고르면, 맨 아래에 해당 조합의 자료가 카드 목록으로 나열된다.

| 층 | 영역 | 역할 |
| :---- | :---- | :---- |
| 1 | 탭 | 어느 출처로 볼지 고른다. 오른쪽 끝에 "저장됨" |
| 2 | 종목 줄 | 어느 종목으로 볼지 고른다 |
| 3 | 콘텐츠 | 선택한 조합의 자료를 카드로 나열한다 |

아래 서술은 이 순서를 따른다.

## 층 1 · 탭

**1\) 탭 구성**

| 순서 | 탭 | 다루는 것 | 데이터 출처 |
| :---- | :---- | :---- | :---- |
| 1 | 유튜브 | 해당 종목 관련 영상 | YouTube Data API |
| 2 | 공시 | 해당 종목의 최근 공시와 요지 | DART 오픈 API |
| 3 | 규제 동향 | 해당 산업에 걸리는 정부 부처 발표 | 정책브리핑 정책뉴스 API (`apis.data.go.kr/1371000/policyNewsService`) |
| 4 | 한국은행 | 기준금리 현황과 변동, 금통위 결정 요지 | 한국은행 ECOS 오픈 API |
| 5 | 미국 Fed | 연방기금금리, FOMC 일정과 최근 결정 | FRED API |
| — | 저장됨 | 사용자가 저장한 카드 모음 | 서비스 자체 데이터 |

**유튜브를 제외한 네 탭은 공공·기관 데이터다.** 출처를 댈 수 있고 검증 가능하다는 점에서 이 제품의 신뢰 기반이 된다.

**탭 순서는 접근성 기준으로 배열한다.** 유튜브와 공시가 앞에 오고, 규제 동향과 금리 관련 탭이 뒤에 온다. 초보 사용자에게 익숙하고 종목과 직결된 정보를 먼저 두는 것이며, **순서에 별도의 의미를 부여하지 않는다.**

첫 진입 시 맨 앞 탭인 유튜브가 선택된 상태로 열린다.

**이 선택에는 대가가 있다.** 차별점 3은 "근거의 출처가 공공기관"인데, 사용자가 처음 보는 화면은 개인 의견이다. 그럼에도 유튜브를 유지하는 이유는 초보 사용자가 진입 즉시 이탈하지 않으려면 익숙한 형태가 먼저 와야 한다고 보기 때문이다. **친숙함을 얻는 대신 첫인상의 신뢰도를 내주는 교환이며, 아래 3)의 보정 장치가 그 대가를 상쇄하는 몫을 진다.**

**"저장됨"은 출처 탭이 아니므로 시각적으로 구분한다.** 앞의 다섯은 자료가 어디서 왔는지를 고르는 축이고, 저장됨은 사용자가 골라 담아둔 것이다. 성격이 다르므로 탭 줄 오른쪽 끝에 배치하고 구분선이나 아이콘으로 나머지와 분리한다.

**2\) 유튜브 탭의 취급**

유튜브는 나머지 넷과 성격이 다르다. 개인 의견이며 사실 검증이 되지 않는다.

- 탭 상단에 \*\*"참고용 · 개인 의견입니다"\*\*를 명시한다  
- **조회수순으로 정렬한다.** 초보 사용자가 "지금 사람들이 이 종목을 어떻게 보고 있는지" 분위기를 파악하는 것이 이 탭의 역할이며, 그 목적에는 조회수가 가장 직관적인 기준이다  
- **다만 조회수는 정확도가 아니다.** 조회수 상위 영상이 맞는 말을 한다는 보장은 없고, 이 정렬은 군중 추종형 사용자에게 쏠림을 강화할 수 있다. 따라서 탭 상단의 "참고용 · 개인 의견입니다" 표시가 이 탭에서는 필수이며, 다른 네 탭보다 눈에 띄게 배치한다  
- 영상 내용을 다른 탭의 요약에 인용하지 않는다. 각 탭의 요약은 해당 탭의 공공 데이터에서만 도출한다

**첫 탭이 유튜브인 데 따르는 보정**

첫 화면이 개인 의견이므로, 이 탭에서만 두 가지를 더 둔다.

| 장치 | 내용 |
| :---- | :---- |
| 참고용 표시 고정 | 스크롤해도 사라지지 않게 탭 상단에 고정한다. 목록 위에 한 번 스치고 지나가면 첫 진입 사용자는 읽지 않는다 |
| 다음 탭 안내 | 목록 하단에 "검증된 자료는 옆 탭에서 볼 수 있어요"를 배치해, 유튜브만 보고 나가지 않도록 다음 행동을 제시한다 |

**측정으로 검증한다.** 유튜브 탭에서 다른 탭으로 이동한 비율을 지표에 추가한다(부록 D). 이 비율이 낮으면 유튜브를 첫 탭에 둔 판단이 틀린 것이며, 탭 순서를 바꾼다.

## 층 2 · 종목 줄

**3\) 종목 선택**

- 탭 바로 아래에 종목 줄이 놓인다. 종목을 선택하면 아래 콘텐츠 영역이 해당 종목 기준으로 바뀐다  
- **선택한 종목은 상위 출처 탭을 바꿔도 유지된다.** 한 종목을 여러 출처로 확인하는 것이 이 구조의 기본 사용 방식이므로, 출처 탭마다 종목을 다시 고르게 하면 흐름이 매번 끊긴다  
- 종목 줄에 "전체" 옵션은 두지 않는다  
- 금액 정보(평단가·수량)는 받지 않는다

**4\) 기본 종목**

- **처음 시작할 때 기본 종목이 미리 등록되어 있다.** 사용자는 아무것도 입력하지 않고 바로 서비스를 쓸 수 있으며, 원하는 종목은 이후에 추가한다  
- 기본 종목은 **시가총액 상위 4개**로 구성한다  
- 첫 진입 시 첫 번째 종목이 선택된 상태로 열린다  
- 기본 종목은 삭제할 수 있다. 다만 전부 삭제하면 화면이 비므로, 마지막 한 개는 삭제 시 안내를 띄운다

**4개로 제한하는 이유** — 칩 노출 한도가 7개이므로 기본 종목을 7개로 채우면 사용자가 자기 종목을 하나만 추가해도 곧바로 "n개 더보기"가 생긴다. 또한 첫 화면이 이미 꽉 차 보이면 추가할 자리가 없다고 느껴져, 이 구조의 핵심 지표인 종목 추가 전환율에 역효과를 낸다. 슬롯이 절반쯤 비어 있어야 "내 종목을 넣는 자리"로 읽힌다.

**입력을 요구하지 않고 시작한다.** 보유 종목 등록을 필수 관문으로 두면 서비스를 경험하기 전에 입력을 요구하게 되고, 그 지점이 단일 급소가 된다. 기본 종목을 미리 채워두면 사용자는 **가치를 먼저 확인한 뒤 자기 종목을 추가**하게 된다.

**5\) "n개 더보기"**

| 상태 | 표시 |
| :---- | :---- |
| 7개 이하 | 모든 종목이 이름이 보이는 칩으로 노출 |
| 8개 이상 | 앞 7개는 칩으로, 나머지는 **"n개 더보기"** 칩 하나로 묶임 |

- "n개 더보기"를 누르면 가려진 종목 목록 창이 열린다  
- 이 창에는 **순서 수정 버튼**이 있어, 앞에 노출할 종목을 사용자가 정할 수 있다  
- 순서를 바꾸면 종목 줄의 노출 순서에 즉시 반영된다  
- 기본 정렬은 **최근 추가 순**이다. 사용자가 방금 추가한 종목이 앞에 오는 것이 자연스럽고, 기본 종목이 뒤로 밀리는 방향이 개인화에도 부합한다

**순서 수정이 이 구조의 필수 조건이다.** 8개 이상이 되는 순간 어떤 종목이 앞 7개에 들어갈지를 서비스가 정하게 되는데, 그 기준을 사용자가 바꿀 수 없으면 정작 자주 보는 종목이 "n개 더보기" 안에 숨는다.

**6\) \+ 버튼**

- **종목 줄 맨 끝에 \+ 버튼을 둔다.** 누르면 종목 추가 창이 열린다. 별도 관리 화면으로 이동하지 않고 종목 줄에서 바로 추가할 수 있어야, 자기 종목이 없다는 것을 인지한 그 자리에서 행동으로 이어진다  
- **\+ 버튼과 "n개 더보기" 칩은 역할이 다르므로 표현을 구분한다.** 전자는 종목 추가, 후자는 가려진 목록 펼치기다. 둘 다 "+"로 시작하면 사용자가 혼동하므로 후자는 텍스트 라벨로 둔다

**종목 추가 창의 구성**

| 요소 | 내용 |
| :---- | :---- |
| 검색 필드 | 종목명 또는 종목 코드 |
| 인기 종목 칩 | 이미 등록된 종목은 선택 불가 처리 |
| 빈 결과 | "검색 결과가 없어요" \+ 철자 확인 안내 \+ 인기 종목 칩 |
| 추가하기 버튼 | 고른 종목을 확정한다. 누르면 창이 닫히고 종목 줄에 추가한 종목이 표시된다 |

**종목을 고르는 즉시 창이 닫히지 않는다.** 사용자가 여러 종목을 연속으로 고를 수 있어야 하며, 하나 고를 때마다 창이 닫히면 다시 열어야 한다. 고른 종목은 창 안에서 선택 상태로 표시되고, **추가하기 버튼을 눌렀을 때** 비로소 확정된다.

**확정 후에도 그 종목 화면으로 자동 이동하지 않는다.** 창만 닫히고 종목 줄에 새 칩이 나타나며, 어느 종목을 볼지는 사용자가 정한다.

**로그인은 여기서 처음 요구한다.** 비로그인 상태에서 추가하기를 누르면 로그인 창이 뜬다. 이미 다섯 탭을 둘러본 뒤이므로 무엇을 위한 계정인지 알고 있다. 로그인하면 고른 종목이 그대로 확정되어야 하며, 로그인 과정에서 선택이 날아가면 그 자리가 새로운 이탈 지점이 된다(부록 B).

**기본 종목을 자기 종목으로 바꾸도록 유도한다.** 기본 종목만 보는 사용자는 개인화 가치를 경험하지 못한다. 화면 상단에 "내가 가진 종목을 추가하면 그 종목 정보를 정리해드려요"를 상시 노출하고, 사용자가 종목을 추가하면 안내를 해제한다.

## 층 3 · 콘텐츠

**7\) 카드 목록**

선택한 탭과 종목의 조합에 해당하는 자료를 **카드 목록으로 나열**한다. 원자료를 그대로 옮기지 않는다. 금통위 결정문과 공시 원문은 인터뷰이들이 읽지 못하겠다고 말한 바로 그 텍스트다.

| 영역 | 내용 |
| :---- | :---- |
| 영향 라벨 | 긍정 / 중립 / 부정 |
| 제목 | **원문 제목을 그대로 쓴다.** 공시 제목, 부처 발표 제목 |
| 주요 내용 | **LLM이 원자료를 읽고 쉬운 말로 생성한다.** 목록에는 두세 줄, 전문은 요약 시트에 |
| 출처와 날짜 | 기관명, 발표일 |
| 원문 링크 | 해당 기관 페이지로 이동 |

**제목은 손대지 않는다.** 요약·가공의 대상은 본문뿐이고 제목은 원문 그대로 옮긴다. 두 가지 이유다.

- **검증 가능성** — 원문 페이지에서 같은 제목을 찾을 수 있어야 사용자가 대조할 수 있다. 제목을 쉬운 말로 바꾸면 원문에 없는 문장이 되어 링크를 눌러도 대응하는 항목을 못 찾는다  
- **역할 분담** — 어려운 제목을 푸는 것은 그 아래 요약의 일이다. 제목까지 풀어 쓰면 요약이 할 일이 없어지고, 사용자는 실제 공시가 어떤 이름으로 불리는지 영영 알지 못한다

`유형자산 취득 결정`처럼 초보가 못 읽는 제목이 그대로 노출되는 것은 의도된 것이다. 바로 아래 요약이 그것을 받는다.

**시각 위계는 제목이 위다.** 카드 목록에서 제목이 가장 돋보이고 요약이 그 아래 보조 텍스트로 붙는다. 목록을 훑을 때 사용자가 자료를 구분하는 단위는 제목이며, 요약이 제목보다 강하면 카드마다 문장 덩어리가 먼저 들어와 훑기가 어려워진다.

**다만 요약이 죽지 않아야 한다.** 제목을 위에 두는 대신 아래 세 가지를 지킨다.

- 요약은 **두 줄 이상 노출한다.** 한 줄로 잘리면 무슨 사안인지 파악되지 않아 카드가 제목만 남은 링크가 된다  
- 요약을 **흐린 회색으로 처리하지 않는다.** 크기로 위계를 주되 대비로 주지 않는다. 읽으라고 만든 문장이다  
- 제목과 요약 사이 간격을 좁게 둔다. 제목을 읽고 막힌 시선이 곧바로 요약으로 이어져야 한다

**모든 탭이 같은 카드 구조를 따른다.** 탭마다 배치가 다르면 사용자가 탭을 옮길 때마다 어디를 봐야 할지 새로 파악해야 한다. 다만 출처의 성격이 달라 일부 요소는 있고 없고가 갈린다. **아래는 무엇이 달라지는지를 고정해두는 표이며, 표에 없는 차이는 만들지 않는다.**

**출처별 카드 구성**

| 요소 | 유튜브 | 공시 | 규제 동향 | 한국은행 | 미국 Fed |
| :---- | :---- | :---- | :---- | :---- | :---- |
| 목록 위 연결 문장 | — | — | — | **있음** | **있음** |
| 썸네일 | **있음** | — | — | — | — |
| 영향 라벨 | — | 있음 | 있음 | — | — |
| 제목 | 영상 제목 (원문) | 공시 제목 (원문) | 발표 제목 (원문) | 지표·결정 제목 | 지표·결정 제목 |
| 주요 내용 (작은 글씨 노출) | — | LLM 요약 | LLM 요약 | LLM 요약 | LLM 요약 |
| 보조 정보 | 채널명 · 조회수 | — | — | 기준금리 값 | 연방기금금리 값 |
| 출처와 날짜 | 채널 · 게시일 | DART · 제출일 | 부처명 · 발표일 | 한국은행 · 발표일 | Fed · 발표일 |
| 원문 링크 | 영상 링크 | 공시 원문 | 발표 원문 | 결정문 페이지 | Fed 페이지 |
| 저장 버튼 | 있음 | 있음 | 있음 | 있음 | 있음 |
| 카드 탭 동작 | **유튜브로 이동** | 요약 시트 | 요약 시트 | 요약 시트 | 요약 시트 |
| 종목에 따라 내용이 바뀌는가 | 바뀜 | 바뀜 | 바뀜 (업종 기준) | **안 바뀜** | **안 바뀜** |

**요약 시트 구성도 탭에 따라 갈린다**

| 시트 요소 | 공시 | 규제 동향 | 한국은행 · Fed |
| :---- | :---- | :---- | :---- |
| 요약 전문 | 있음 | 있음 | 있음 |
| 라벨 판단 이유 | 있음 | 있음 | — |
| 용어 풀이 드래그 | 있음 | 있음 | 있음 |
| 저장 · 원문 보기 | 있음 | 있음 | 있음 |

유튜브 탭은 시트가 없다. 요약도 라벨도 없어 담을 것이 없으므로 탭하면 곧바로 영상으로 나간다.

**탭별로 추가되는 규칙**

| 탭 | 추가 규칙 |
| :---- | :---- |
| 유튜브 | 목록 상단에 "참고용 · 개인 의견입니다"를 스크롤해도 사라지지 않게 고정. 목록 하단에 다음 탭 안내. 조회수순 정렬 |
| 공시 | 요약 입력이 제목과 공시 유형까지로 제한됨. 제목에 없는 수치를 생성하지 않음 |
| 규제 동향 | API가 이미지 URL을 주더라도 화면에 표시하지 않음. 조회 기간 3개월, 비면 "최근 관련 발표가 없어요" |
| 한국은행 · Fed | 목록 위 "내 종목엔" 문장 1회. 카드 자체는 모든 종목에 동일하므로 종목을 바꿔도 카드가 그대로인 것이 정상 |
| 저장됨 | 카드마다 **저장 당시의 탭과 종목**을 배지로 표시. 내용은 저장 시점으로 고정되며 원문 링크만 살아 있는 링크 |

**차이가 세 곳에만 몰려 있다.** 라벨 유무, 시트 유무, 종목 반영 여부. 나머지 요소는 다섯 탭이 모두 같은 자리에 같은 형태로 둔다. **디자인 단계에서 탭별 카드를 따로 그리지 말고 하나의 컴포넌트에 요소를 켜고 끄는 방식으로 만든다.**

**요약의 입력 범위를 제한한다**

| 탭 | 요약 입력 | 이유 |
| :---- | :---- | :---- |
| 공시 | **공시 제목 \+ 공시 유형**까지. 본문 원문은 읽지 않는다 | 공시 원본파일을 내려받아 파싱하려면 문서 포맷별 처리가 붙어 일정 안에 들어오지 않는다 |
| 규제 동향 | API가 제공하는 본문 텍스트 | 별도 파싱 없이 확보된다 |
| 한국은행·미국 Fed | 지표 값과 결정 요지 텍스트 | 원자료가 짧다 |

**이 제한의 대가를 문서에 남긴다.** 공시 요약은 본문을 읽고 만든 것이 아니므로, 제목에 없는 내용(계약 금액, 상대방, 조건)은 요약에 담기지 않는다. 즉 이 탭의 요약은 **"제목이 무슨 뜻인지 풀어주는 수준"이며, 원문을 대체하지 않는다.** 상세는 원문 링크로 넘긴다.

- 공시 유형(유상증자 결정, 단일판매·공급계약 체결 등)은 그 자체로 정보량이 크다. 유형별로 무엇을 뜻하는지 설명하는 문장을 붙이면 제목 말바꿈을 넘어선다  
- **금액·수량 등 제목에 없는 수치는 생성하지 않는다.** 없는 값을 그럴듯하게 채우는 것이 이 제한에서 가장 큰 위험이다  
- 원문 이동률(부록 D)이 높게 나오면 요약이 부족한 것이므로, 그때 본문 파싱을 다음 단계로 올린다

**카드를 탭하면 요약 시트가 펼쳐진다**

카드 목록에 담기는 것은 요약 두세 줄까지다. 그 이상을 목록에 넣으면 훑어보는 기능이 사라진다. 카드를 탭하면 홈 위에 시트가 올라오고, 그 안에 해당 자료에 관한 것이 모두 모인다.

| 시트 구성 | 내용 |
| :---- | :---- |
| 제목 · 출처 · 날짜 | 카드와 동일 |
| 영향 라벨과 판단 이유 | 목록에서는 라벨만, 시트에서는 판단 이유까지 |
| 요약 전문 | 목록의 두세 줄보다 길어도 된다 |
| 용어 풀이 안내 | "모르는 단어는 드래그해보세요" |
| 저장 | 카드와 같은 동작 |
| 원문 보기 | 해당 기관 페이지로 이동 |

**용어 풀이가 실제로 쓰이는 자리가 여기다.** 좁은 카드 목록에서 단어를 드래그하는 것은 모바일에서 사실상 불가능하다. 본문이 펼쳐진 시트가 있어야 드래그 호출이 동작한다.

**시트는 별도 페이지가 아니다.** 홈 위에 뜨는 창이므로 한 페이지 구조와 URL 규칙을 그대로 따른다. 닫으면 보고 있던 탭과 종목이 그대로 남는다.

**원문은 이 사이트 안에서 열지 않는다**

시트 안에 원문 페이지를 끼워 넣는 방식(iframe)은 세 가지 이유로 채택하지 않는다.

- **기관 사이트가 대체로 외부 삽입을 차단한다.** 차단되면 빈 화면이 뜨는데, 링크가 죽은 것처럼 보이는 쪽이 아무것도 하지 않는 것보다 나쁘다  
- **통과하더라도 화면이 깨진다.** 기관 사이트는 데스크톱 기준이라 모바일 폭에서 가로 스크롤이 생긴다. 못 읽어서 만든 서비스가 원문을 더 나쁜 조건으로 보여주게 된다  
- **남의 페이지를 우리 틀 안에 넣는 것은 링크와 성격이 다르다.** 저작권 취급이 달라진다

따라서 원문 보기는 **새 탭으로 원 매체에서 연다.** 원문 링크의 역할은 읽을거리가 아니라 검증 통로다. 요약이 미덥지 않을 때 확인하러 가는 문이며, 그래서 원문 이동은 사용자가 의도적으로 한 번 더 누른 결과여야 한다.

> **개발 착수 전 확인** — 기관 사이트의 외부 삽입 차단 여부는 실제로 넣어보면 10분 안에 확인된다. 위 판단은 차단을 전제로 하고 있으므로, 확인 결과가 다르면 첫 번째 이유만 사라지고 나머지 둘은 남는다.

**유튜브 탭은 예외다.** 요약도 라벨도 없으므로 시트에 담을 것이 없다. 영상을 탭하면 곧바로 유튜브로 이동한다.

**한국은행·미국 Fed 탭은 카드 위에 연결 문장을 둔다**

이 두 탭의 원자료는 종목과 무관하다. 기준금리 2.50%는 어느 종목을 골라도 같은 값이므로, 카드만 나열하면 종목 칩을 눌러도 화면이 바뀌지 않는다. 사용자는 클릭이 작동하지 않는 것으로 오해한다.

따라서 두 탭에 한해 카드 목록 위에 **"내 종목엔"** 문장을 배치한다.

| 영역 | 내용 |
| :---- | :---- |
| **내 종목엔** | 이 지표가 선택한 종목에 어떤 의미인지 한두 줄 |
| 카드 목록 | 금리 지표와 결정 요지 (모든 종목 공통) |

> **한국은행 · SK하이닉스** 내 종목엔 — 금리 동결이 이어지면 성장주 밸류에이션에 걸리는 압박이 줄어드는 쪽으로 봐요 ───────────── 기준금리 2.50% (2026.07 동결) 금통위는 물가 안정세를 근거로 동결을 결정했어요 한국은행 · 2026.07.10 · 원문 보기

**이 문장은 단정하지 않는다.** 금리가 특정 종목에 유리한지 불리한지는 해석이 갈리는 사안이며, 그래서 이 두 탭에는 긍정·부정 라벨을 붙이지 않기로 했다. 문장으로 같은 단정을 하면 앞뒤가 맞지 않는다.

- **"\~쪽으로 봐요", "\~하는 경향이 있어요"처럼 여지를 남기는 어미를 쓴다.** "유리해요", "좋아요" 같은 단정형은 쓰지 않는다  
- 종목의 업종과 성격(성장주·배당주·수출주 등)에 근거해 일반적으로 알려진 관계만 서술한다  
- 이 문장은 다른 세 탭에는 두지 않는다. 공시·규제 동향은 카드마다 영향 라벨이 그 역할을 하고, 유튜브는 판단을 붙이지 않는다

**LLM으로 생성한다.** 종목이 늘어날 때마다 문장을 사람이 쓰는 방식은 확장되지 않으므로, 종목 정보와 현재 금리 지표를 입력으로 문장을 생성한다. 다만 이 문장은 사용자가 사실로 받아들이는 유일한 해석이므로 생성 조건을 좁게 건다.

| 항목 | 규칙 |
| :---- | :---- |
| 입력 | 종목의 업종·성격, 현재 금리 지표와 최근 변동 방향 |
| 길이 | 한두 줄. 길어지면 근거 없는 설명이 늘어난다 |
| 금지 | 주가 방향 예측, 매수·매도 시사, 수치 단정 |
| 어미 | 여지를 남기는 형태로 고정 |
| 실패 처리 | 조건을 만족하는 문장을 만들지 못하면 문장을 비우고 카드만 노출한다 |

**같은 종목·같은 지표에는 같은 문장이 나와야 한다.** 새로고침할 때마다 표현이 달라지면 사용자는 이것이 계산된 결과가 아니라 매번 지어내는 말임을 알아챈다. 지표가 갱신되기 전까지는 생성 결과를 캐싱해 고정한다.

**캐시 단위는 종목이 아니라 업종이다.** 입력이 "종목의 업종·성격 \+ 금리 지표"이므로, 같은 업종의 종목은 같은 문장을 받는다. 종목 단위로 캐싱하면 같은 결과를 종목 수만큼 다시 만들게 된다. 캐시 키는 `업종 + 지표 스냅샷`으로 잡고, 지표가 갱신될 때만 무효화한다.

**대신 문장이 종목명을 부르지 않는다.** 업종 단위 문장이므로 "SK하이닉스에는"이 아니라 "반도체처럼 설비 투자 비중이 큰 업종에서는" 식으로 쓴다. 종목명을 넣으면 그 종목만을 분석한 결과처럼 읽히는데, 실제로는 업종 수준의 일반론이다. **읽히는 정밀도와 실제 정밀도를 일치시킨다.**

**시연에 쓸 종목의 문장은 팀이 직접 검수한다.** LLM 생성이므로 잘못된 관계를 그럴듯하게 서술할 수 있고, 이 문장은 화면에서 가장 먼저 읽히는 자리에 놓인다.

**8\) 영향 라벨 — 긍정 / 중립 / 부정 3단계**

AI가 자료를 읽고 선택한 종목 기준으로 어느 쪽인지 판별해 카드에 표시한다.

- **퍼센트로 표기하지 않는다.** "긍정 70%"는 무엇을 센 숫자인지 정의할 수 없으면서 측정값처럼 보인다. 또한 여러 카드의 퍼센트를 사용자가 합산하면 사실상 매수·매도 신호가 되어, 판단을 대신하지 않는다는 원칙과 투자자문 경계 양쪽에 걸린다  
- **판단 이유를 한 줄 함께 표시한다.** "설비 투자 확대는 중장기 생산능력에 긍정이지만 단기 비용 부담이 있어 중립으로 봤어요." 라벨만 있으면 근거 없는 단정이 되고, 이유가 붙으면 사용자가 스스로 검토할 수 있다  
- **애매하면 중립으로 보낸다.** 한쪽으로 단정하는 오류가 중립으로 두는 오류보다 비용이 크다  
- **라벨을 정렬 기준으로 쓰지 않는다.** 긍정 카드만 위로 모으면 사용자가 원하는 쪽만 읽게 되어 확증편향을 키운다

**라벨의 생성 단위**

| 탭 | 생성 단위 | 이유 |
| :---- | :---- | :---- |
| 공시 | 자료 1건 \= 종목 1개 | 공시는 특정 회사의 것이므로 종목과 1:1이다 |
| 규제 동향 | **자료 1건 × 업종 1개** | 부처 발표 하나는 그 산업의 모든 종목에 걸린다. 종목 단위로 만들면 사용자가 종목을 추가할 때마다 생성량이 곱으로 늘어난다 |

규제 발표를 종목 단위로 판별하면 같은 발표에 대해 같은 업종의 종목마다 라벨을 새로 만들게 된다. **판단 근거가 "이 산업에 지원인가 규제인가"인 이상 결과도 업종 단위로 같으므로, 업종 단위로 한 번 만들어 해당 업종의 종목에 공유한다.** 생성량이 종목 수가 아니라 업종 수로 고정된다.

**라벨을 붙이지 않는 탭이 있다**

| 탭 | 영향 라벨 | 이유 |
| :---- | :---- | :---- |
| 유튜브 | 없음 | 영상 내용은 개인 의견이며, 자막이 없으면 판별 자체가 불가능하다. 유튜브를 근거로 인용하지 않기로 한 원칙과도 충돌한다 |
| 공시 | 있음 | 수주·계약·증자 등 종목에 직접 걸리는 사안이라 판별 가능성이 가장 높다 |
| 규제 동향 | 있음 | 산업 지원책과 규제 강화는 방향이 비교적 뚜렷하다 |
| 한국은행 | 없음 | 금리 동결이 특정 종목에 긍정인지 부정인지는 해석이 갈린다. 대신 카드 위에 여지를 남긴 "내 종목엔" 문장을 둔다 |
| 미국 Fed | 없음 | 위와 동일 |

**금리 탭에 라벨을 붙이지 않는 것은 기능 누락이 아니라 판단이다.** 해석이 갈리는 사안에 단정적 라벨을 붙이는 것은 "없는 확신을 파는" 행위이며, 이 제품이 하지 않기로 한 일이다.

**예시 구성:**

> **공시 · SK하이닉스** `긍정` 유형자산 취득 결정 반도체 생산 설비에 대규모 투자를 결정했어요. 생산능력이 늘어나는 방향입니다. 단기 비용 부담은 있지만 중장기 공급 확대 요인이라 긍정으로 봤어요. DART · 2026.08.10 · 원문 보기

**9\) 초보자를 위한 이해 보조**

타겟이 초보인데 공시와 금통위 결정문의 용어가 그대로 나가면 "읽었지만 이해하지 못하는" 상태가 서비스 안에서 재현된다.

**용어 풀이 — 드래그로 호출한다**

사용자가 카드 본문에서 모르는 단어를 드래그하면, LLM이 **그 카드의 문맥에 맞는 설명**을 제시한다.

| 항목 | 규칙 |
| :---- | :---- |
| 호출 방식 | 텍스트 드래그 |
| 대상 | 요약 시트의 본문 어디든. 사전에 등록한 용어 목록에 한정하지 않는다 |
| 입력 | 드래그한 텍스트 \+ 해당 자료의 요약 본문 |
| 출력 | 한두 줄 설명 |

**문맥을 함께 넣는 것이 이 방식의 핵심이다.** 같은 단어라도 맥락에 따라 뜻이 달라진다. "발행"은 공시에서는 주식 발행이고 금리 탭에서는 국채 발행이다. 사전 정의 방식은 이 구분을 못 하지만, 카드 본문을 함께 넘기면 그 자리에 맞는 설명이 나온다.

**정의만 하고 판단은 하지 않는다.** "유상증자란 새 주식을 발행해 자금을 조달하는 것"까지가 범위이며, "그래서 주가에 부정적입니다"는 넣지 않는다. 영향 판단은 카드의 라벨이 담당한다.

**본문에 어려운 용어를 미리 표시하지 않는다.**

밑줄이나 색으로 특정 단어만 표시하면 세 가지 문제가 생긴다.

- **드래그 방식의 장점을 없앤다.** 어디든 드래그할 수 있다는 것이 이 방식의 이점인데, 표시된 단어만 눌리는 것처럼 보이면 나머지는 시도하지 않게 된다  
- **"어렵다"의 기준을 정할 수 없다.** 같은 단어라도 사용자마다 다르다. AI가 자동 판별하게 하면 카드마다 기준이 흔들리고, 사전 목록으로 고정하면 목록에 없는 단어는 영영 표시되지 않는다  
- **표시가 많아지면 본문이 읽히지 않는다.** 공시 요약처럼 전문 용어 밀도가 높은 글은 문장 절반에 밑줄이 그어진다

**대신 기능의 존재를 알린다.** 첫 진입 시 안내를 한 번 노출하고("모르는 단어는 드래그해보세요"), 이후에는 요약 시트 상단에 작은 힌트를 상시 배치한다. 무엇이 어려운지는 서비스가 정하지 않고 사용자가 정한다.

**10\) 카드 저장**

카드마다 저장 버튼을 둔다. 누르면 그 카드가 "저장됨" 탭에 담긴다.

| 항목 | 규칙 |
| :---- | :---- |
| 위치 | 카드 우측 상단 |
| 대상 | 모든 탭의 모든 카드 (유튜브 영상 포함) |
| 해제 | 다시 누르면 저장 해제 |
| 보관 위치 | 탭 줄 오른쪽 끝의 "저장됨" |

**저장은 이력과 다르다.** 앞서 열람 이력(히스토리)을 범위에서 뺀 것은 자동으로 쌓이는 기록이 사용자에게 쓸모가 없었기 때문이다. 저장은 사용자가 의도적으로 고른 것이므로 다시 열어볼 이유가 있다. **이 기능이 계정을 유지할 실질적 근거가 된다.**

**저장됨 탭의 구성**

- 저장한 카드를 최근 저장 순으로 나열한다  
- 각 카드에 어느 탭·어느 종목에서 저장했는지를 표시한다. 출처 맥락이 없으면 왜 저장했는지 기억나지 않는다  
- 종목 줄은 그대로 두고 필터로 동작한다. 특정 종목을 고르면 그 종목에서 저장한 카드만 보인다  
- 비어 있을 때는 "관심 있는 카드를 저장해두면 여기서 모아볼 수 있어요"를 노출한다

**저장한 카드의 내용은 저장 시점 그대로 고정한다.** 원자료가 갱신되거나 요약이 다시 생성되면 사용자가 저장했던 것과 달라진다. 저장 시점의 제목·요약·라벨·날짜를 함께 보관하고, 원문 링크만 살아 있는 링크로 둔다. **링크가 만료된 경우에도 저장한 요약은 남아 있어야 한다.**

---

**별도의 학습 코너를 만들지 않는다.** 투자 입문 가이드는 이미 공적 영역에서 충분히 제공된다. 금융감독원 e-금융교육센터는 500개가 넘는 맞춤형 콘텐츠를 무료로 제공하며 인증 체계까지 운영하고, 금융투자협회 산하 금융투자교육원은 일반 투자자 교육과 고위험 상품 사전교육을 담당한다. 그럼에도 20대 금융이해력은 하락했다. **콘텐츠 부족이 원인이 아니므로 자료를 하나 더 만드는 것은 이미 실패가 확인된 처방이다.**

---

**최종 결과물**

탭에서 출처를 고르고 종목을 고르면, 그 조합의 자료가 초보가 읽을 수 있는 카드로 정리되어 나열된다. 사용자는 여러 사이트를 돌지 않고도 자기 종목에 걸리는 것들을 한자리에서 확인한 상태가 된다.

### 2.3 차별점

**1\. 흩어진 공공 데이터를 종목 기준으로 모은다** 한국은행 금통위 결정, Fed 금리, 부처 정책 발표, DART 공시는 모두 공개되어 있지만 각각 다른 사이트에 있고 종목과 연결되어 있지 않다. 이것들을 한 종목 아래 모아 보여주는 서비스는 없다.

**2\. 어려운 원자료를 초보가 읽을 수 있게 정리한다** 금통위 결정문과 DART 공시는 공개되어 있지만 초보 투자자가 읽어내기 어렵다. 각 카드는 원자료를 쉬운 말로 요약하고, 공시와 규제 발표는 종목에 미치는 영향을 긍정·중립·부정으로 표시한다. **다만 공시 탭의 요약은 제목과 공시 유형을 푸는 수준이며 본문을 대체하지 않는다(층 3 참조). 여기서 하는 일은 "이 제목이 무슨 사안인지" 알려주는 것까지다.** 금리 탭은 그 지표가 내 종목에 어떤 의미인지를 한 줄로 잇는다. 모르는 용어는 드래그하면 그 문맥에 맞는 설명이 나온다.

**3\. 근거의 출처가 공공기관이다** 개인 의견이나 커뮤니티 여론이 아니라 중앙은행과 정부 부처, 전자공시 데이터를 쓴다. 유튜브는 참고용으로 명확히 구분한다.

**4\. 예측을 팔지 않는다** 매수·매도를 권하지 않고, 앞으로 오를지 내릴지도 말하지 않는다. 확인 가능한 자료와 그 요약까지만 제시한다. 확신을 파는 대신 한계를 밝히는 것이 신뢰 기반이다.

### 3.2 사용자 시나리오

**상황** — 김도희 씨는 SK하이닉스를 보유 중이다. 아침에 금리 관련 뉴스를 보고 자기 종목이 걱정된다.

**1\. 진입** assit을 연다. 상단에 탭 줄, 그 아래에 종목 줄, 맨 아래에 카드 목록이 이미 채워져 있다. 아무것도 입력하지 않았는데 화면이 살아 있다.

**2\. 종목 선택** 종목 줄에 기본 종목 네 개가 있고 SK하이닉스가 보인다. 없었다면 끝의 \+ 버튼으로 추가했을 것이다. SK하이닉스를 누른다.

**3\. 공시 탭** 탭을 공시로 옮긴다. 종목 선택은 그대로 유지된다. 카드마다 `긍정` `중립` 라벨이 붙어 있고, 제목만으로는 뭔지 몰랐던 항목에 쉬운 말 요약이 있다. 모르는 용어를 누르니 설명이 뜬다.

**4\. 규제 동향 탭** 반도체 지원 정책 관련 부처 발표 카드가 보인다. 원문을 다 읽지 않아도 무슨 내용인지, 어느 방향인지 파악된다.

**5\. 한국은행 탭** 맨 위에 "금리 동결이 이어지면 성장주 밸류에이션에 걸리는 압박이 줄어드는 쪽으로 봐요"가 있고, 그 아래에 기준금리 값과 금통위 결정 요지가 있다. **금리 뉴스와 자기 종목이 처음으로 한 문장으로 이어진다.**

**6\. 저장** 공시 카드 하나가 나중에 다시 보고 싶다. 카드 우측 상단의 저장 버튼을 누른다. 여기서 처음으로 로그인 창이 뜬다. **다섯 탭을 다 둘러본 뒤이므로 무엇을 위해 계정을 만드는지 이미 안다.** 로그인하면 카드가 탭 줄 끝의 "저장됨"에 담긴다.

**7\. 이탈** 예전 같으면 유튜브 세 개와 커뮤니티를 돌았을 시간이다. 살지 말지는 도희 씨가 정한다. **다만 이번엔 "왜 그런지 모르겠다"는 상태가 아니다.**

## 부록 A. 정보 구조

**화면 위계 (위에서 아래로)**

| 순서 | 영역 | 내용 |
| :---- | :---- | :---- |
| 1 | 탭 | 유튜브 / 공시 / 규제 동향 / 한국은행 / 미국 Fed / 저장됨 |
| 2 | 종목 줄 | 종목 칩 · "n개 더보기" · \+ 버튼 |
| 3 | 콘텐츠 | 선택한 탭 × 선택한 종목의 정리 결과 |

**출처가 1차 축, 종목이 2차 축이다.** 상단에서 어느 출처를 볼지 고르고, 그 아래에서 어느 종목으로 볼지 고른다.

**종목 선택은 탭을 바꿔도 유지된다.** SK하이닉스를 고른 상태에서 한국은행 탭에서 공시 탭으로 넘어가면 여전히 SK하이닉스가 선택되어 있어야 한다. 탭마다 종목을 다시 고르게 하면 한 종목을 여러 출처로 확인하는 흐름이 매번 끊긴다.

**페이지 목록** 서비스 소개 → 홈(탭 \+ 종목 줄 \+ 콘텐츠)

홈이 유일한 본 페이지다. 요약 시트, 종목 추가, 순서 수정, 로그인, 계정·설정은 별도 페이지가 아니라 홈 위에 뜨는 창으로 처리한다.

**로그인은 관문이 아니라 특정 행동의 조건이다.** 이전 구조에서는 로그인이 첫 페이지였는데, 그러면 "입력을 요구하지 않고 시작한다"는 온보딩 원칙과 정면으로 충돌한다. 종목 등록을 필수 관문에서 뺀 자리에 로그인을 앉히면 급소가 위치만 옮긴 것이다.

**한 페이지 구조**

별도의 내비게이션을 두지 않는다. 목적지가 홈 하나이므로 메뉴를 만들 이유가 없다.

- 탭이나 종목을 바꾸면 콘텐츠 영역만 갱신된다. 페이지 전체를 갈아끼우지 않아야 여러 출처와 종목을 오가며 보는 흐름이 끊기지 않는다  
- 계정·설정은 화면 구석의 아이콘으로 진입한다

**URL 구조를 설계한다.** 탭과 종목이 각각 URL에 반영되어야 특정 조합을 북마크하거나 공유할 수 있다. 웹의 이점이며, 브라우저 뒤로 가기도 정상 동작해야 한다.

## 부록 B. 계정과 온보딩

**계정** — 등록 종목과 저장한 카드를 기기와 무관하게 유지하기 위해 둔다. 개인정보는 최소로 수집하고, 탈퇴 시 등록 종목과 저장 카드를 함께 삭제한다.

**로그인 없이 시작한다.** 첫 진입 사용자는 계정 없이 홈에 들어와 기본 종목 네 개로 다섯 탭을 모두 열람할 수 있다. 로그인을 요구하는 시점은 두 곳뿐이다.

| 행동 | 로그인 | 이유 |
| :---- | :---- | :---- |
| 다섯 탭 열람, 종목 전환 | 불필요 | 가치를 먼저 확인하게 한다 |
| **종목 추가** | 필요 | 기기와 무관하게 유지되어야 의미가 있다 |
| **카드 저장** | 필요 | 저장이 계정을 유지할 실질적 근거다 |

- 비로그인 상태는 임시 세션으로 다루고, **로그인하면 그때까지의 상태를 계정으로 옮긴다.** 옮기지 않으면 사용자가 방금 한 일이 사라지고, 그 지점이 새로운 이탈 급소가 된다  
- 로그인 요구 창에는 왜 필요한지를 한 줄로 밝힌다("추가한 종목을 다음에도 보려면 로그인이 필요해요")  
- **첫 진입 이탈률(부록 D)은 로그인 벽 뒤가 아니라 홈 도달 기준으로 측정된다.** 로그인을 관문에 두면 이 지표 자체가 의미를 잃는다

**온보딩** — 종목 등록을 필수로 요구하지 않는다. 기본 종목이 미리 등록된 상태로 홈에 진입한다.

- 첫 진입 시 서비스 소개 화면 1\~2장 후 바로 홈으로 이동한다  
- 기본 종목은 시가총액 상위 4개로 구성한다  
- 종목 목록 끝의 **\+ 버튼**으로 추가한다. 별도 관리 화면 진입 없이 목록에서 바로 열린다  
- **평단가·수량 등 금액 정보는 받지 않는다**  
- 종목 추가는 인기 종목 칩 선택과 검색 두 경로를 제공한다  
- 검색 결과가 없을 때의 빈 결과 화면을 설계한다. 필수 관문은 아니지만 여기서 막히면 개인화가 시작되지 않는다

**종목 목록 표시 규칙** — 7개까지는 종목명 칩으로 노출하고, 8개째부터는 "n개 더보기" 칩으로 묶는다. 이 칩을 누르면 가려진 종목 목록과 순서 수정 기능이 있는 창이 열린다. 기본 정렬은 최근 추가 순이다.

**종목 추가 창의 구성은 본문 층 2를 따른다.** 여러 종목을 고른 뒤 추가하기 버튼으로 한 번에 확정하며, 확정 후에도 그 종목 화면으로 자동 이동하지 않는다.

**종목 마스터 데이터가 모든 탭의 전제다**

종목코드·종목명·업종·시가총액이 없으면 검색도, 기본 종목 산출도, 공시 조회도, 규제 필터링도 성립하지 않는다. 다섯 개 API 중 어느 것도 이 데이터를 주지 않는다.

| 항목 | 용도 |
| :---- | :---- |
| 종목코드·종목명 | 검색, 종목 칩 |
| 시가총액 | 기본 종목 4개 산출 |
| **업종 분류** | 규제 동향 부처 매핑, "내 종목엔" 문장, 영향 라벨의 업종 단위 생성 |
| **DART 고유번호** | 공시 조회 |

업종 분류는 세 기능이 동시에 물고 있으므로, 분류 체계를 도중에 바꾸면 세 곳이 함께 흔들린다. **분류 체계를 먼저 하나로 고정한다.**

**DART는 종목코드로 조회되지 않는다**

DART 오픈 API는 종목코드가 아니라 **8자리 고유번호(`corp_code`)** 를 인자로 받는다. `corpCode.xml`을 호출하면 고유번호·회사명·종목코드·최근변경일자가 담긴 압축 파일을 받을 수 있으므로, 이를 풀어 종목코드 ↔ 고유번호 매핑표로 적재한다. 이 표가 없으면 공시 탭은 한 건도 불러오지 못한다.

또한 고유번호 없이 공시를 검색하면 조회 기간이 3개월로 제한된다. 종목별 조회가 전제인 이 구조에서는 문제가 되지 않지만, 매핑이 빠진 종목은 자동으로 그 제약을 받는다.

**유튜브 쿼터는 종목 수에 곧바로 걸린다**

YouTube Data API는 검색 1회에 100유닛을 쓰고 프로젝트 기본 할당량은 하루 10,000유닛이다. **하루 약 100회 검색이 상한이며, 종목 하나를 갱신하는 데 검색 1회가 든다.** 등록 종목이 늘면 곧바로 한도에 닿는다.

- 검색 응답에는 조회수 값이 없다. 조회수순 정렬은 정렬 옵션으로 되지만 **화면에 조회수를 표시하려면 영상 조회 호출이 한 번 더 필요하다**(50건 묶음, 1유닛)  
- 소비량을 자체 집계한다. 잔여 쿼터는 응답으로 오지 않는다  
- 한도에 닿으면 신규 검색을 멈추고 직전 캐시를 그대로 노출한다. 빈 화면을 보이지 않는다  
- **시연에 쓸 종목은 발표 전에 미리 캐시를 채워둔다.** 당일 쿼터 소진은 발표 실패와 같다

**갱신은 일 단위 배치로 한다**

이 제품의 목표가 아닌 것에 "속보 전달"이 있다. 실시간 갱신은 그 목표와 무관하면서 쿼터와 비용만 소모한다.

| 대상 | 주기 |
| :---- | :---- |
| 다섯 탭 자료 수집 | 1일 1회 배치 |
| 사용자가 종목을 새로 추가한 경우 | 그 종목만 즉시 1회 수집 |
| 종목 마스터 | 1일 1회 |
| DART 고유번호 매핑 | 주 1회 |

사용자 요청을 받은 자리에서 외부 API를 직접 부르지 않는다. 외부 장애가 그대로 서비스 장애가 된다.

**정책브리핑 이용 조건** — 텍스트는 공공누리 출처표시 조건으로 비상업적 이용이 가능하다. 사진·이미지·영상은 문체부가 저작권 전부를 보유하지 않으므로 사용하지 않는다. API가 이미지 URL을 제공하더라도 화면에 표시하지 않는다.

**규제 동향 탭의 필터링** — 정책브리핑 API는 부처 정보를 함께 제공한다. 종목의 산업에 해당하는 부처를 선별해 조회하고, 종목명·산업 키워드로 한 번 더 거른다.

- **이 표는 코드가 아니라 데이터로 관리한다.** 설정 파일이나 DB 테이블에 두어야 매핑을 고칠 때마다 배포하지 않는다  
- 부처명은 2025년 10월 정부조직 개편(산업통상자원부 → 산업통상부, 환경부 → 기후에너지환경부 등)을 반영했다. **API가 실제로 반환하는 부처 값과 문자열이 일치하는지 개발 착수 시 대조한다.** 조직 개편이 다시 있으면 이 표가 먼저 깨진다  
- 매핑에 없는 업종은 조회하지 않고 "최근 관련 발표가 없어요"로 처리한다. 무관한 발표를 띄우는 것보다 낫다

**갱신 주기가 탭마다 다르다.** 금리는 상시, 공시는 수시, 규제 발표는 몇 주에 한 번이다. 규제 동향 탭은 조회 기간을 최근 3개월로 넓게 잡고, 그래도 비면 "최근 관련 발표가 없어요"를 명시한다.

**뉴스 데이터 원칙** — 기사 본문 전문은 저장소에 커밋하지 않는다. 원문 링크는 새 탭으로 원 매체에서 연다.

## 부록 D. 성공 지표

| 지표 | 측정 대상 | 판단 기준 |
| :---- | :---- | :---- |
| 종목 추가 전환율 | 기본 종목에서 자기 종목으로 넘어가는가 | **이 구조의 핵심 지표.** 낮으면 개인화가 작동하지 않는 것이며, 추가 유도 방식을 재설계해야 한다 |
| 첫 진입 이탈률 | 홈 도달 대비 첫 종목 탭 진입 | 기본 종목이 흥미를 끌지 못하면 여기서 빠진다 |
| 탭 도달률 | 출처 탭 다섯이 실제로 쓰이는가 | 특정 탭 도달률이 현저히 낮으면 해당 탭을 재검토 |
| 유튜브 → 타 탭 이동률 | 첫 탭을 유튜브로 둔 판단이 맞는가 | **낮으면 사용자가 개인 의견만 보고 나가는 것이며, 공공 데이터가 신뢰 기반이라는 전제가 무너진다.** 탭 순서를 바꾼다 |
| 로그인 전환율 | 종목 추가·카드 저장 시점의 로그인 완료 비율 | 낮으면 로그인 요구 지점 자체를 재검토 |
| 시트 열람률 | 카드 목록에서 요약 시트로 들어가는가 | 낮으면 목록의 두세 줄에서 멈추는 것이며, 라벨 이유·용어 풀이가 전달되지 않는다 |
| 시트 대비 원문 이동률 | 요약이 충분한가 | **시트를 연 뒤 원문으로 나가는 비율로 잰다.** 지나치게 높으면 요약이 제 역할을 못 하는 것이며, 공시 탭에서 높게 나오면 본문 파싱을 다음 단계로 올린다 |
| 외부 채널 탐색 감소 | 핵심 가치의 검증 | 테스트 시 자기보고 |
| 카드 저장률 | 저장 기능이 쓰이는가 | 낮으면 저장 버튼의 위치나 필요성을 재검토 |
| 재방문 | 리텐션 | 저장됨 탭 재진입 비율과 함께 본다 |
